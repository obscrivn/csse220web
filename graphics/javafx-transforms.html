Manipulating JavaFX Objects

Backgrounds and layer order

Add background rectangles to a drawing Pane first, then the object Groups, then foreground text. Later children normally draw over earlier children. A background added last can hide the whole drawing.

Rectangle sky = new Rectangle(0, 0, 500, 220);
sky.setFill(Color.LIGHTSKYBLUE);
Rectangle ground = new Rectangle(0, 220, 500, 140);
ground.setFill(Color.LIGHTGREEN);
Pane drawing = new Pane(sky, ground);
drawing.getChildren().add(objectView);

These snippets assume the referenced objectView has already been created, and use javafx.scene classes. For a resizable solid panel background, a Region can instead use setBackground(new Background(new BackgroundFill(Color.WHITE, CornerRadii.EMPTY, Insets.EMPTY))). The shape background approach matches the fixed-size homework drawing area.

One object, one local coordinate system

Construct a meaningful object from several shapes inside one Group. Keep its shapes in local coordinates. A createView() method can return a newly built Group; store x, y, angle, and color in private fields initialized by the object's constructor. Each instance should use its own data.

Group view = new Group(body, detail, marker);
view.setTranslateX(x);
view.setTranslateY(y);
return view;

Construct new body/detail/marker nodes on each call. Do not cache and return the same Group to several parents. Reuse your object-building code, not the individual Node instances. Use a loop to create multiple object instances at distinct positions.

Translation moves the whole object

view.setTranslateX(160);
view.setTranslateY(120);
// Later: move 20 units to the right.
view.setTranslateX(view.getTranslateX() + 20);

Translation changes where the Group appears without rewriting every child's x/y values. Positive x moves right; positive y moves down. Prefer a plain Pane for a coordinate drawing; a layout container may arrange children for you.

Rotation needs an angle and a pivot

Rotate turn = new Rotate(30, 0, 0);
view.getTransforms().add(turn);
// Change this existing transform instead of adding another every click.
turn.setAngle(turn.getAngle() + 15);

Import javafx.scene.transform.Rotate. Angles are in degrees. Pivot (0,0) is in the Group's local coordinates; choose a meaningful point for your design. If its center is (30,10), use new Rotate(angle,30,10). Translate the Group to place that local origin in the drawing Pane. In ordinary screen coordinates a positive rotation appears clockwise.

setRotate(angle) instead uses the layout-bounds center as pivot. An explicit Rotate avoids a pivot that changes when you add more shapes. Transform order matters: rotate local geometry, then use the Group translation to position the object. Unlike old Swing drawing code, this does not modify a shared drawing context that must be restored.

Scale and reset

setScaleX(1.5) and setScaleY(1.5) enlarge a node's view; the convenience scale properties use its bounds center. Required homework geometry uses original shape coordinates, so do not scale the fixed Part 1 tasks instead of supplying the specified sizes. For creative objects, consider how scale and rotation affect visibility.

view.setTranslateX(startX);
view.setTranslateY(startY);
turn.setAngle(0);
view.setScaleX(1);
view.setScaleY(1);

Shape getters such as Rectangle.getX() describe local geometry. getBoundsInParent() includes transforms. A shape can retain the same local x yet appear elsewhere after moving its Group.

Check your understanding

  1. Predict two 20-unit moves from x=160. Confirm the view ends at x=200.
  2. Rotate a three-shape object; all parts should stay together.
  3. Make a second instance; moving one must not move the other.
  4. Check backgrounds remain behind both objects and that neither is clipped.
