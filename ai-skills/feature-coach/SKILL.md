# Feature Coach

Use when: we need a feature or technique we do not yet understand.
1. Read the named code and restate current and desired behavior.
2. Identify the model object that should own the state/rule.
3. Explain the unfamiliar technique briefly; identify assumptions.
4. Suggest the smallest input-to-model-to-display increment.
5. Stay within the task's files, agreed APIs, and Java 21/JavaFX stack.
6. Implement that increment; do not add unrelated features or libraries.
7. Explain the diff and give normal, edge, and repeat checks.
8. Report checks actually run separately from manual checks still needed.
Done when: we can explain the change and verify the stated behavior.
