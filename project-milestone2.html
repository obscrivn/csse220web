Milestone 2: Build Your Functional Alpha

This week: make one small workflow work from beginning to end.

Live check-in: Monday, November 9, 2026, in class. All four teammates demonstrate and explain the running app. The instructor assigns the grade during check-in. No separate Canvas submission.

Friday: full-day team development. Work together in your dedicated pod (see team assignments). Use the Friday plan below.

1. Focus on one workflow

Use your existing JavaFX project. Choose two small, connected core actions from your approved idea. The first changes your model; the second uses that changed state. Keep one usable screen and enough feedback to see what happened.

Write your target: “The user can ___, then ___; the app shows ___.” Agree on what counts as working before coding.

ProjectA realistic connected pair
GameMove to collect one item → use that item to open one gate.
Math solver / learning appSolve one supported problem → revisit its result in session history. Or answer a question → see progress update.
SimulationSet a parameter → step the simulation and see its effect.
UtilityAdd a task → mark that same task complete.
VisualizationFilter a dataset → select a remaining item to see its details.

These are examples, not additional requirements. A greeting button, static mockup, or two unrelated demos is insufficient. Leave extra levels, screens, sound, persistence, and visual polish for later unless essential to your chosen workflow.

2. Skills you MUST demonstrate for Milestone 2

Each teammate must be able to explain their part and follow the shared workflow. The team demonstrates these skills in one integrated app.

  • Run and share: open the existing project, run it in IntelliJ, and get the latest main through GitHub Desktop.
  • Connect events to objects: trace a user action → model method/state change → visible result.
  • Assign responsibilities: explain which object owns the data/rule; update UML for the classes you actually implemented.
  • Use AI for an unfamiliar feature: give a small task with context and boundaries; explain what you accepted, changed, or rejected.
  • Verify and debug: predict a result, reproduce a failure, and check normal, edge, and repeated use.
  • Integrate safely: commit your work, review a teammate’s change, merge through a PR, and rerun the combined app.

Open the AI Skills Hub for a worked learning process, good task examples, and reusable agent instructions. No extra framework, class quota, or installed skill pack is required.

3. Use your one week well

  1. Before Friday: choose the workflow, sketch class responsibilities, and agree on method inputs/outputs. Split work across four teammates: first action/model, second action/model, GUI connection, and integration/testing. Everyone contributes and reviews; the integration role is active work, not waiting.
  2. Friday opening: meet in your dedicated pod. Everyone runs the same main. Confirm the workflow and file owners; identify one unfamiliar technique to investigate with AI.
  3. Friday build: implement and test small changes on branches. Use the AI Hub’s learn → try → verify routine. Merge the first action early, then connect the second to the same state.
  4. Friday integration: stop adding features. Merge reviewed work one PR at a time; all four pull main and run the whole workflow. Fix broken connections before polishing.
  5. Before Monday: repeat the three checks below, update UML, and rehearse the check-in. List remaining work with owners. Do not add a new feature at the cost of the working demo.

Use the GitHub integration walkthrough. Need a technique? See events/state (Lab 12), animation/reset (Lab 13), keyboard/object interactions (Lab 15), or the UML guide.

4. Run three checks

Keep one short table: input/action | expected | actual | fix/retest.

  1. Normal: complete both actions in order; confirm that action two uses action one’s state.
  2. Edge: try one relevant invalid input, unavailable action, or boundary. The state stays consistent and the user gets useful feedback.
  3. Repeat: run again or reset/restart. Check for stale results, duplicate effects, or state that failed to reset.

Manual GUI checks are enough; show existing automated tests if useful. For the AI-assisted change, work out the expected result yourself and include it in these checks.

5. Monday check-in: show these five things

  • Working app: run latest main and demonstrate your two connected actions on a usable screen.
  • Objects: show updated UML and trace one action through the actual source.
  • Checks: show the normal, edge, and repeat results.
  • Team and AI: each teammate explains their contribution; show commits/reviewed PRs and one verified AI-assisted feature. Keep Help Citation and AI-LEARNING-LOG.md current under the syllabus policy.
  • Next: name the unfinished core work, its owners, and any blocker.

Keep these in your existing repository/shared document. No separate slide deck or new report is required. Be ready to explain your code, not just run it.
