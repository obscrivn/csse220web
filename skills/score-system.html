Skill 04: Add a Score System

Keep score in a model object, award points exactly once, show the score, and reset it on purpose.

1 Mission

Collecting the orb in Lab 15 shows a message, but the player has no sense of progress. A score fixes that. Scoring also brings classic bugs: points awarded twice, a score that never resets, and a label that shows an old value.

Your mission: award points when the orb is collected, show "Score: …" in the header, and reset it correctly, with the score logic in its own small class.

Why you might need this: game points, quiz correct-answer counts, progress in a practice app, or "tasks completed" in a utility.

2 What you already know

  • Lab 12 (Treasure Clicker) is a score system: a gold field, buttons that add 10 or 25, an updateDisplay() helper that calls setText, and a Reset. You already know that changing the int alone does not change the label.
  • Lab 15: collection happens in checkCollision, and crystal.isVisible() stops the orb from being collected twice.
  • Encapsulation: private fields, public methods that enforce rules.

3 Learn the concept

Score is application state, so give it an owner

In Lab 12 the score lived in the Application class. That works for one counter. In a project, the score usually has rules: no negative awards, a best score, maybe bonuses. Rules belong in a small model class with no JavaFX imports, so you can test it on its own.

Shape of a score class (you write the bodies) 
public class ScoreKeeper {
    private int score = 0;

    public void addPoints(int points) { /* rule: ignore points <= 0? */ }
    public int getScore()            { /* ... */ }
    public void reset()              { /* ... */ }
}

The three-step pattern for every scoring event

// inside the event handler or collision check
score.addPoints(ORB_POINTS);   // 1. tell the model what happened
updateScoreLabel();            // 2. refresh the view from the model
status.setText("...");         // 3. optional feedback

The handler does not compute score + 10 itself. It tells the model, then reads from the model to update the label. If you later add a bonus rule, only ScoreKeeper changes.

When does the score change? Exactly once per achievement

Lab 15 calls checkCollision from three places: every Timeline tick, after every arrow key, and after Rotate. If the drone sits on the orb for 40 ticks, a careless version awards points 40 times. The fix is a guard condition, a fact that becomes false right after the award. You already have one: crystal.isVisible().

A hidden node still has bounds. Hiding the orb does not stop intersects(...) from returning true. The visibility check is what prevents duplicate scoring. Skill 08 shows what happens without it: one orb worth hundreds of points.

Not a game? How this transfers
  • Quiz: award a point when a question is answered correctly, and only the first time. The guard is "this question is still unanswered".
  • Practice app: track a streak and a best streak, with the same addPoints / reset / getBest idea.
  • Utility: a "completed tasks" counter. Marking an already-completed task must not count twice.

5 Design before coding

  1. Events: list every event that should change the score, such as collecting an orb, finishing a level, or a time bonus. For each one, what is the guard that keeps it from counting twice?
  2. Rules: can points be negative? Is there a maximum? Is there a best score that survives a reset?
  3. Ownership: which class owns the number? Which class decides how many points an orb is worth: the score keeper, the level, or a constant in ArrowApp?
  4. Reset meaning: does Reset mean "try this level again" (keep score?) or "new game" (clear score)? If you did Skill 02, what does loadLevel do to the score?

6 Guided implementation

  1. Create ScoreKeeper.java in your package, with a private int field and the three methods above. No JavaFX imports.

    Check: it compiles. Optional: write the check class from Step 6 now.

  2. Add fields to ArrowApp: one ScoreKeeper, one Label for the score, and a named constant such as private static final int ORB_POINTS = 10; instead of a "magic number".
  3. Show the score. Add the score label to header. Write a small updateScoreLabel() helper, as in Lab 12's updateDisplay(), and call it once before stage.show() so the label starts with Score: 0.
  4. Award points in one guarded place. Inside the existing visible-orb block of checkCollision, tell the score keeper, then update the label.
    Hint: where exactly?

    Right next to crystal.setVisible(false);. Anything outside that if runs on every tick and key press.

    Check: collecting the orb shows Score: 10. Pressing arrows afterward does not change it.

  5. Reset deliberately. In the Reset handler, or in loadLevel if you did Skill 02, call score.reset() and then updateScoreLabel(), following your Step 5 decision.
  6. Check the model without the GUI (recommended). Create a small class next to ScoreKeeper, such as ScoreKeeperCheck. Its main method uses the model and prints PASS or FAIL, so you can see that the rules work before any window opens. 
    /** Quick checks for ScoreKeeper. No JavaFX, no extra setup. */
public class ScoreKeeperCheck {
    public static void main(String[] args) {
        ScoreKeeper s = new ScoreKeeper();
        s.addPoints(30);
        s.reset();
        check("reset clears score", s.getScore() == 0);
        // TODO: more checks (two awards add up, a rule from Step 5, ...)
    }

    private static void check(String name, boolean ok) {
        System.out.println((ok ? "PASS " : "FAIL ") + name);
    }
}

    How to run a check class: click the green arrow next to main and choose Run. Results appear in the Run window. This works because the class has no JavaFX in it. Your app still runs with the Maven goal javafx:run, as in the labs. You do not need to change pom.xml or add a test folder.

    Add at least two more checks of your own. Rerun the class whenever you change ScoreKeeper.

7 Test your skill

  • NormalThe app starts with Score: 0. Collect the orb by steering, and separately by pressing Start: the score becomes 10 each time.
  • EdgeAfter collecting, keep pressing arrows, press Rotate, and steer back and forth over the orb's old spot: the score stays at 10. If you have a rule such as "no negative points", add it to your check class.
  • Repeat / resetCollect → Reset → collect: the score matches your design (10 again, or 20). Do it three times. The label always matches the model, never an old value.

8 Extend the skill

Challenge: award points for how well the objective was done

Make a fast collection worth more. Count Timeline ticks since Start (each tick is 20 ms), and when the orb is collected award, for example, max(10, 100 - ticks / 5). Decide which class owns the tick count, and make sure Reset clears it. Add a best score that survives Reset, and add checks for both rules to your check class before you connect them to the GUI.
