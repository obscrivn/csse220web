Skill 06: Read Input from the User

Let the user choose a drone level and type a speed. Check the input, convert it, and respond helpfully to bad entries.

  • CategoryData and user input
  • DifficultyBeginner

  • EffortAbout 1–2 hours

1 Mission

So far, users talk to your app only with buttons and arrow keys. Most projects also need values: a level to play, a speed, an answer, a coefficient, a task name. Users make typos, leave boxes empty, and type "fast" where you expected a number.

Your mission: add a level picker (ComboBox) and a speed box (TextField) with an Apply button. Valid input changes the drone. Invalid input shows a helpful message and never crashes the app.

This is the most transferable skill in the hub: math solvers, quizzes, converters, and planners all read and validate input the same way.

2 What you already know

  • Lab 12: Button + setOnAction, a Label for feedback, and controls added to a VBox.
  • Lab 15: canvas.requestFocus() sends keys back to the arena after a button click.
  • Errors & Exceptions (Week 8): a try / catch block lets your program recover from an exception instead of stopping.
  • Strings: trim(), isEmpty(), equals / equalsIgnoreCase.

ChoiceBox<T> works almost the same as ComboBox and is fine for short lists. Both are in javafx.scene.control, and so is TextField.

Choosing beats typing

If there is a fixed set of valid answers (levels, units, difficulty), use a ComboBox. The user cannot enter something invalid. Use a TextField only when the value is truly open-ended.

Validate in three gates

The middle gate: converting text to a number 
int speed;
try {
    speed = Integer.parseInt(text);        // "7" → 7
} catch (NumberFormatException e) {        // "abc", "3.5", "" all land here
    feedback.setText("\"" + text + "\" is not a whole number.");
    return;                                // stop; keep the old speed
}
  • Integer.parseInt(" 7") throws, because the spaces are not digits. Always trim() first.
  • Double.parseDouble reads decimals and throws the same NumberFormatException for text like "abc". It happens to ignore surrounding spaces, but trim anyway so every field behaves the same way.
  • Catch the specific exception. An empty catch (Exception e) {} hides real bugs.

The focus trap

When the user types in a TextField, it has keyboard focus, so the arrow keys move the text cursor, not the drone. After applying input, call canvas.requestFocus(), just as Lab 15 does after each button.

5 Design before coding

  1. Choose vs. type: for each value your app needs, should the user choose it or type it?
  2. Rules: for each typed value, write the gates: required? whole number or decimal? range? Write the exact message for each failure.
  3. When to read: on an Apply button, on Enter (TextField.setOnAction), or both? Reading on every keystroke is usually unnecessary.
  4. Where the rules live: GUI code reads text and shows messages. Should "speed must be 1–10" live in the model, such as SceneToken or a settings class, so it is enforced no matter who sets the speed?
  5. Bad input: keep the previous valid value, or reset to a default?

6 Guided implementation

  1. Make speed changeable in SceneToken: replace the constant with an instance field and add a setter (and a getter if useful). Update step(...) to use the field.

    Check: the app behaves exactly as before at speed 3.

  2. Add the level picker. Create a ComboBox<String>, add your level names, and set a default with setValue. Add it to controls with a small Label. Import javafx.scene.control.ComboBox.
  3. React to a choice. In the ComboBox's setOnAction, read getSelectionModel().getSelectedIndex(), then stop flight, reset the drone, move or show the orb for that level (or call loadLevel), update status, and request canvas focus.
    Hint: where do the orb positions come from?

    If you have not done Skill 02, two small arrays indexed by level are enough, such as {390, 440, 60} for x. If you have, use your Level objects.

    Check: choosing Level 2 moves the orb and puts the drone back at the start.

  4. Add the speed box and an Apply button plus a feedback Label.
  5. Write one method that applies the speed, such as applySpeed(String raw, ...), and call it from both Apply and the TextField's setOnAction (Enter) so the logic is not duplicated. Inside it: trim → empty gate → parse gate (try/catch) → range gate → set the speed → success message → canvas.requestFocus().

    Check: typing 7 and pressing Enter makes Start fly faster, and the arrow keys work immediately afterward.

  6. Make the messages specific. "Enter a speed from 1 to 10." is more helpful than "Invalid input."

8 Extend the skill

Challenge: validation you can test without a GUI

Move the three gates into a plain Java method, such as static int parseSpeed(String text) in a small class with no JavaFX, that returns the speed or throws an IllegalArgumentException whose message is the user-facing text. The GUI then has a single try / catch that shows e.getMessage(). Then write a small check class (the Skill 04, Step 6 pattern) that prints PASS or FAIL for every row of your table. This is exactly the separation that Skill 07 relies on.
