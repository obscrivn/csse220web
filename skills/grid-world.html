Skill 05: Build a Grid World

Store a tile map in a 2D array, draw it, block walls, and move the drone one cell at a time.

1 Mission

Many projects are not about smooth pixels. They are about cells: a maze, a board game, a tile puzzle, a seating chart, a heat map. In a grid world, positions are whole numbers (row, column), and the rules ask questions like "is that cell open?"

Your mission: turn the Drone Arena into a 5 × 3 grid. Walls block movement, each arrow key moves exactly one cell, and the drone can reach the orb only through open cells.

2 What you already know

  • 2D arrays (early weeks): int[][] grid = new int[rows][cols];, grid.length is the number of rows, grid[0].length is the number of columns, and nested for loops visit every cell.
  • Graphics Hub / Homework Scenes: drawing Rectangles at computed positions in a loop; GridPane exists for laying out controls.
  • Lab 15: arrow keys in setOnKeyPressed; the 500 × 300 canvas Pane; the 90 × 90 drone in SceneToken.

3 Learn the concept

Rows go down, columns go across

Store the map as cells[row][col]. The row is like y (down the screen) and the column is like x (across). This order is the opposite of (x, y), and mixing them up is the most common grid bug.

// 0 = open, 1 = wall
int[][] cells = {
    {0, 0, 0, 1, 0},     // row 0    . . . # .
    {0, 1, 0, 1, 0},     // row 1    . # . # .
    {0, 1, 0, 0, 0}      // row 2    . # . . .
};                       //   col:   0 1 2 3 4
cells.length      // 3 rows
cells[0].length   // 5 columns
cells[1][3]       // row 1, col 3 -> 1 (a wall)

Grid position ↔ screen position

With square tiles of size TILE pixels, the top-left corner of a cell is at:

x = col * TILE;      // column → x
y = row * TILE;      // row    → y

col = (int) (x / TILE);   // a mouse click at (x, y) → which cell?
row = (int) (y / TILE);

Drawing the tiles: one Rectangle per cell

for (int row = 0; row < /* number of rows */; row++) {
    for (int col = 0; col < /* number of cols */; col++) {

Moving means "ask the model, then redraw"

The model decides whether a move is legal. The view only places the drone where the model says it is. Each direction is a change in (row, col): Up is (-1, 0), Down (+1, 0), Left (0, -1), Right (0, +1).

Check the bounds before you read the array. cells[-1][0] or cells[3][0] throws ArrayIndexOutOfBoundsException. Valid rows are 0 to rows - 1, so use <, not <=.

Not a game? How this transfers
  • Board games: tic-tac-toe and Connect Four are grids, with "occupied" meaning which player owns the cell.
  • Simulation: Conway's Game of Life is a grid updated on each Timeline tick (see Skill 01).
  • Math: a Sudoku checker, a matrix visualizer, or a grid of function values colored as a heat map.
  • Utility: a seating chart or calendar month view: click a cell, and the model updates.

5 Design before coding

  1. Cell values: what can a cell hold? Open or wall only? A goal? An item? Choose int codes with named constants (OPEN, WALL), or boolean[][] blocked if there are only two kinds.
  2. Model class: a GridWorld class with no JavaFX could own the array and the player's row and column. Which methods does it need? Consider getRows(), getCols(), isInBounds(r, c), isOpen(r, c), tryMove(dRow, dCol), and a reset.
  3. View responsibilities: which class draws tiles and converts (row, col) to pixels? Where does TILE live?
  4. Reset: both the model position and the view position must return to the start. What happens if you reset only one of them?

6 Guided implementation

  1. Create GridWorld.java with the array, the player's row and column, the start position, and the methods from your design. Write isInBounds first, and isOpen should call it.

    Check: it compiles. Strongly recommended: write a GridWorldCheck class now that prints PASS or FAIL for edges, corners, and walls. It uses the same pattern as Skill 04, Step 6, and needs no setup.

  2. Add a field and a constant to ArrowApp: a GridWorld built from your layout and start cell, and TILE.
  3. Draw the tiles with the nested loop above, right after the canvas is created and before the drone is added. Walls get a solid fill. Open cells can be transparent with a light stroke so you can see the grid.

    Check: you see the grid lines and walls in the correct cells. Compare with your array literal one cell at a time.

  4. Add placeAt(x, y) to SceneToken and a helper in ArrowApp that converts the model's (row, col) to pixels, including the centering offset, and calls it. Call the helper once at startup.
    Hint: the centering offset

    The tile is 100 pixels and the drone is 90, so (TILE - 90) / 2 = 5 pixels on each side. Cell (row 0, col 0) puts the drone at (5, 5).

  5. Move with the keys. In setOnKeyPressed, each arrow calls tryMove with its (dRow, dCol). If it returns true, re-place the drone and call checkCollision. If it returns false, give feedback such as "Blocked."

    Check: each tap moves exactly one cell, walls and edges block, and no exceptions appear in the Run window.

  6. Put the orb in a cell by setting its center to the middle of a tile: col * TILE + TILE / 2. Your existing collision check still works.
  7. Reset both model and view. Reset calls the model's reset and then your placement helper.

7 Test your skill

  • NormalWalk an open path to the orb. Each key press moves exactly one cell in the expected direction, and the orb is collected when you enter its cell.
  • EdgeFrom each corner, press both arrow keys that point outward: no movement, no exception. Try to enter every wall from every side. In your check class: isInBounds(rows - 1, cols - 1) is true, and isInBounds(rows, 0) is false.
  • Repeat / resetMove, then Reset: the drone is back at the start cell on screen, and the next move starts from there, which proves the model was reset too. Hold an arrow key: key repeat moves one cell per repeat and stops at walls.

8 Extend the skill

Challenge: build the map from text

Write the layout as strings, such as "...#.", ".#.#.", ".#...", and convert them into the 2D array in a constructor, using charAt(col) or toCharArray(). Add a goal character such as 'G' so the orb position comes from the map too. Then a new level (see Skill 02) is just a different array of strings. Watch out for rows of different lengths.
