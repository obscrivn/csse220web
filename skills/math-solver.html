Skill 07: Build a Math Solver Interface

Put the math in a plain Java class, connect it to text fields, handle the special cases, and test it without the GUI.

  • CategoryApplication logic
  • DifficultyIntermediate
  • ConceptsModel/view separation, double math, special cases, String.format, checks with main
  • PrerequisitesLab 12; Skill 06 recommended
  • EffortAbout 1.5–3 hours
1 Mission2 Already know3 Concept4 Lab 155 Design6 Build7 Test8 Extend9 AI Coach10 Unlocked

1 Mission

Math solvers, calculators, converters, and statistics tools all share one shape: read numbers → compute → show a result. The danger is putting the math inside a button handler, where you can test it only by clicking, and where it gets tangled with parsing and display.

Your mission: build a small solver for the linear equation ax + b = c. The math lives in a class that knows nothing about JavaFX. The window reads three coefficients, asks that class for the answer, and handles every special case clearly. You will prove the math works with a small check class before you connect the GUI.

Scope: the user types the three coefficients into separate boxes. Do not try to parse a whole typed equation like "2x+3=11" or build a symbolic algebra system. That is a much larger project, and it is not needed to show good design.

2 What you already know

  • Lab 12: controls in a layout, a button handler, a Label updated with setText.
  • Skill 06: reading a TextField, trim(), Double.parseDouble, catching NumberFormatException.
  • Testing habits from homework: work out the expected answer first, then compare it with what the code produces.
  • Algebra: ax + b = c → ax = c − b → x = (c − b) / a, when a ≠ 0.

Dividing a double by zero does not crash. 3.0 / 0.0 is Infinity and 0.0 / 0.0 is NaN ("not a number"). Only int division by zero throws an ArithmeticException. If you forget the a = 0 check, your app silently shows x = Infinity. Check the special cases before dividing.

Shape of the model class

/** a*x + b = c. Pure Java, no JavaFX. */
public class LinearEquation {
    private final double a;
    private final double b;
    private final double c;

    public LinearEquation(double a, double b, double c) { /* store them */ }

    public boolean hasUniqueSolution()          { /* when is there exactly one x? */ }
    public boolean hasInfinitelyManySolutions() { /* ... */ }
    public boolean hasNoSolution()              { /* ... */ }

    public double solve() {
        // If there is no unique solution, refuse:
        //   throw new IllegalStateException("No unique solution when a is 0");
        // Otherwise return the formula.
    }
}

Two details about double

  • Rounding: 0.1 + 0.2 is 0.30000000000000004. In checks, compare with a tolerance: Math.abs(actual - expected) < 1e-9. For display, format: String.format("x = %.4f", x) → x = 0.3333.
  • Negative zero: for −2x + 5 = 5, the formula gives (5 − 5) / −2 = -0.0, which displays as -0.0000. Adding 0.0 to the result turns -0.0 into 0.0. A small detail, but users notice it.

Other project types that use this skill
  • Other solvers: quadratic, systems of two equations, triangle solver, interest and loan calculator.
  • Unit converters: a Converter model with a convert(amount, from, to) method, tested without the GUI.

5 Design before coding

  1. Inputs and outputs: what exactly does the user enter, and what exactly should they see in each case? Fill in the special-case table for your problem before you code.
  2. Model API: which methods does the view need? Should the model return a number, a boolean, or a message? (Hint: math classes usually return values, and the view decides the wording.)
  3. Who validates what: "Is this text a number?" is a view question. "Is a zero?" is a math question. Write which class answers each one.
  4. Mutability: should a LinearEquation object ever change after it is created, or should each Solve create a new one?
  5. Tests first: write down 5 equations and their correct answers, worked out by hand. These become your checks.

6 Guided implementation

  1. Write the checks first. In the same package as your app, create LinearEquationCheck.java with a main method. Two checks to get you started: 
    /** Quick checks for LinearEquation, worked out by hand. No JavaFX, no extra setup. */
public class LinearEquationCheck {
    public static void main(String[] args) {
        checkClose("2x + 3 = 11 -> 4", new LinearEquation(2, 3, 11).solve(), 4.0);
        check("0x + 2 = 5 -> no solution", new LinearEquation(0, 2, 5).hasNoSolution());
        // TODO: your own checks
    }

    private static void checkClose(String name, double actual, double expected) {
        check(name + " (got " + actual + ")", Math.abs(actual - expected) < 1e-9);
    }

    private static void check(String name, boolean ok) {
        System.out.println((ok ? "PASS " : "FAIL ") + name);
    }
}

    Add your own checks for: infinitely many solutions, a negative a, a fractional answer such as 3x + 1 = 2, and the -0.0 case.

    How to run a check class: click the green arrow next to main and choose Run. Results appear in the Run window. This works because the class has no JavaFX in it. Your app still runs with the Maven goal javafx:run, as in the labs. You do not need to change pom.xml or add a test folder.

    Check: the check class does not compile yet. That is expected, because LinearEquation does not exist.

  2. Create LinearEquation in the same package and fill in the methods until every line says PASS. Do not open any window yet.
    Hint: checking that solve() refuses

    Call it inside a try. If the next line runs, print FAIL. In catch (IllegalStateException e), print PASS.

  3. Build the view. Three TextFields inside an HBox with Labels between them ("x +", "="), so the window looks like the equation. Add a Solve Button and a result Label in a VBox.
  4. Write solveClicked(). Parse all three fields inside one try, show a message and return on NumberFormatException, create the model, then use an if / else if / else on the special cases. Use String.format for the answer.

    Check: 2, 3, 11 shows x = 4.0000; 0, 2, 2 shows the "every x" message.

  5. Add a Clear button that empties the fields and resets the result message. TextField has a clear() method.

7 Test your skill

  • NormalEvery line of your check class says PASS. In the window: 2x + 3 = 11 → 4; −1x + 0 = 5 → −5; 3x + 1 = 2 → 0.3333.
  • Edge0x + 2 = 2 and 0x + 2 = 5 show the right messages, never Infinity or NaN. −2x + 5 = 5 shows 0.0000, not -0.0000. An empty box or two shows the input message.
  • Repeat / resetSolve one equation, change one coefficient to invalid text, and press Solve: the old answer must disappear and the error message must show. Clear, then solve a new equation: no leftover text.

8 Extend the skill

Challenge: a quadratic solver that reuses your linear one

Create QuadraticEquation for ax² + bx + c = 0 using the discriminant b² − 4ac: two real roots, one repeated root, or no real roots. When a = 0 it is not quadratic at all, so delegate to your LinearEquation (rearranged as bx + c = 0). Write the checks first, including a discriminant that is "almost zero" because of rounding. A ComboBox (Skill 06) can let the user choose linear or quadratic.
