Skill 09: Load Levels and Game Objects from a File

Move level data out of Java code and into a text file. Read it, turn each line into an object, and report bad lines clearly.

  • CategoryData and user input
  • DifficultyIntermediate
  • ConceptsgetResourceAsStream, Scanner, split, parsing, error messages with line numbers
  • PrerequisitesSkill 02 recommended, Lab 13 resources folder, Errors & Exceptions (Week 8)
  • EffortAbout 2–3 hours

1 Mission

In Skill 02, each level is a line of Java code. Adding or moving one orb means editing Java, recompiling, and hoping nothing else broke. Real games keep that data in files. A teammate can design levels in a text editor while you work on the code.

Your mission: put the Drone Arena's levels in a text file. Each level can have any number of orbs and walls. Read the file when the app starts, build objects from each line, and show a clear message (with the line number) when the file has a mistake.

Why you might need this: game levels, quiz questions, practice problems for a solver, starting data for a simulation, or a sample task list for a planner.

2 What you already know

  • Lab 13 Setup B: files in src/main/resources are found at runtime with a path that starts at /, such as /images/drone.png. Text files work the same way.
  • Skill 02: a plain Level data class, a list of levels, a current index, and one loadLevel method.

  • Errors & Exceptions (Week 8): throwing an exception with a helpful message.
  • Java basics: Scanner, ArrayList, for loops over a list, String.split.

3 Learn the concept

Where the file lives

Put data files next to your images, in src/main/resources. Maven copies everything there into the running program, so the same path works on every teammate's computer.

src/
  main/
    java/demo/ArrowApp.java ...
    resources/
      images/drone.png        → found as "/images/drone.png"
      levels/levels.txt       → found as "/levels/levels.txt"

Design a file format people can read

One object per line, starting with a keyword that says what kind of object it is. Comments and blank lines make the file easy to edit.

src/main/resources/levels/levels.txt 
# Drone Arena levels. Lines starting with # are comments.
# LEVEL name          starts a new level
# ORB x y             an energy orb centered at (x, y)
# WALL x y w h        a wall rectangle

LEVEL Warm-up
ORB 390 205

LEVEL The Wall
ORB 440 60
ORB 60 40
WALL 320 0 20 200

Three layers: text → data objects → shapes on screen

Reading every line of a resource file

getResourceAsStream is the text-file partner of the getResource call that loads drone.png. It returns null when the file is not found, so check for that and say what is wrong.

public static List<String> readLines(String resourcePath) {
    InputStream in = LevelLoader.class.getResourceAsStream(resourcePath);   // import java.io.InputStream
    if (in == null) {
        throw new IllegalArgumentException("Cannot find " + resourcePath
                + ". Is it inside src/main/resources?");
    }
    List<String> lines = new ArrayList<>();
    Scanner scanner = new Scanner(in);
    while (scanner.hasNextLine()) {
        lines.add(scanner.nextLine());
    }
    scanner.close();
    return lines;
}

Parsing one line

String line = lines.get(i).trim();
if (line.isEmpty() || line.startsWith("#")) {
    continue;                                  // skip blanks and comments
}
String[] parts = line.split("\\s+");           // "ORB 440 60" → ["ORB", "440", "60"]
String keyword = parts[0].toUpperCase();
if (keyword.equals("ORB")) {
    // TODO: check that there are exactly 3 parts
    current.addOrb(new Orb(Double.parseDouble(parts[1]), Double.parseDouble(parts[2])));
} else if (keyword.equals("WALL")) {
    // TODO
} // ...

"\\s+" means "one or more spaces or tabs", so extra spaces between numbers do not matter.

Bad lines must not crash the game silently

People make typos in data files. Your loader should stop at the first problem and say exactly where it is. These are the real messages from a working loader:

Line 2: not a number in "ORB 1 two"
Line 2: expected "ORB x y"
Line 3: unknown keyword "TREE"
Line 1: ORB appears before any LEVEL line
Level "A" has no ORB
Cannot find /levels/nope.txt. Is it inside src/main/resources?

Variable numbers of objects change the reset rule. In Skill 02 you added the orb and wall to the canvas once and moved them. Now each level can have a different number of orbs and walls, so loadLevel must remove the previous level's shapes before adding new ones. Keep them in a list such as List<Circle> orbNodes, then call canvas.getChildren().removeAll(orbNodes) and orbNodes.clear().

5 Design before coding

  1. Format: write a sample file by hand before any code. Which keywords? Which numbers, in which order? Write the format in comments at the top of the file.
  2. Classes: which classes hold the data (Level, Orb, Wall)? Which class reads and parses the file? None of these needs JavaFX. Which class turns data into shapes?
  3. Errors: list what can go wrong (missing file, bad number, wrong count, unknown keyword, a level with nothing in it) and the message for each.
  4. When to read: once at startup, or every time a level loads? Once is simpler and catches mistakes before anyone plays.
  5. Failure: if the file is broken, what does the player see?

6 Guided implementation

  1. Create the file. In IntelliJ's Project view, right-click src/main/resources → New → Directory → levels, then right-click levels → New → File → levels.txt. Write two levels in your format. Make Level 1 match Lab 15: one orb at (390, 205).
  2. Create the data classes with no JavaFX imports: small Orb and Wall classes with final fields and getters, and a Level with a name and two lists, with methods such as addOrb and getOrbs.
  3. Create LevelLoader with the readLines method above.

    Check: a quick check class that prints readLines("/levels/levels.txt").size() shows the number of lines in your file.

  4. Write parse(List<String> lines). Loop with an index so you know the line number (i + 1). Skip blanks and comments. LEVEL starts a new Level and adds it to the result list. ORB and WALL add to the current level.
    Hint: the level name can contain spaces

    "LEVEL The Wall" splits into three parts. Use line.substring(parts[0].length()).trim() to get everything after the keyword.

  5. Add the error messages. Start every message with "Line " + (i + 1) + ": ". Wrap the branches in try and turn a NumberFormatException into your own message. After the loop, reject a file with no levels and a level with no orbs.
  6. Check the loader without the GUI. Use the Skill 04 check-class pattern. List.of(...) lets you write a small "file" right in the check, so you can test bad lines without creating bad files: 
    List<Level> levels = LevelLoader.parse(List.of("LEVEL A", "ORB 1 2"));
check("one level", levels.size() == 1);

try {
    LevelLoader.parse(List.of("LEVEL A", "ORB 1 two"));
    check("bad number is rejected", false);
} catch (IllegalArgumentException e) {
    check("bad number -> " + e.getMessage(), e.getMessage().contains("Line 2"));
}

    Check: every check prints PASS, including one for each error in your Step 5 design list.

  7. Load at startup. At the top of ArrowApp.start, call the loader inside try. On IllegalArgumentException, show a Label with the message in a simple scene, then return.
  8. Rebuild shapes in loadLevel. Remove the old orb and wall shapes from canvas and clear your lists. Then create one Circle per Orb and one Rectangle per Wall, add them to your lists, and add the lists to canvas. Reset the drone and update the level label.
  9. Update checkCollision to loop over the walls (crash) and the orbs (hide each one touched). When no orb is visible, load the next level, or show a win message after the last one.

    Check: Level 2 from your file appears with all of its orbs and walls, exactly where the file says.

7 Test your skill

  • NormalLevels appear in file order, with every orb and wall where the file says. Now edit only the text file (move an orb, add a third level) and rerun: the game changes without any Java edit.
  • EdgeBreak the file on purpose, one mistake at a time: ORB 1 two, ORB 1, TREE 3 4, a level with no orb, and a misspelled file name. Each one shows a clear message with the line number, and nothing crashes. Fix the file afterward.
  • Repeat / resetPress Reset five times on a level with walls, then temporarily print canvas.getChildren().size(): the number must not grow. Finish every level, including the last one.

8 Extend the skill

Challenge: choose a level pack

Create two files, such as levels/easy.txt and levels/hard.txt. Add a ComboBox on a welcome screen (Skill 06, Skill 03) that chooses which file to load. The loader does not change at all; only the path does. That is the payoff of keeping reading and parsing separate from the GUI.

Reading vs. saving: files in src/main/resources are part of your program, so treat them as read-only. Saving player data, such as a best score, needs a file somewhere else, like the user's home folder. That is a different skill, so ask your instructor before adding it.
