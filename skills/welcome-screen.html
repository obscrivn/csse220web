Skill 03: Add a Welcome Screen

Open on a start screen, play the game, and return to the menu without losing track of your app's state.

1 Mission

Your Drone Arena drops the player straight into the game. Many apps start with a welcome screen that shows the title, short instructions, and a Play button. A Menu button in the game returns to it.

Your mission: add a welcome screen and the two-way navigation. Then make a deliberate decision about whether the game keeps or resets its state when the player comes back.

Milestone 2 reminder: one usable screen is enough for your alpha. Add screens after your core workflow works, unless a second screen is essential to that workflow.

2 What you already know

  • Lab 12: Application, Stage, Scene, and VBox; Button.setOnAction runs a lambda when clicked.
  • Graphics Hub: layout containers (VBox, HBox, BorderPane, GridPane) and the Stage → Scene → root structure.
  • Lab 15: after a button click, canvas.requestFocus() sends the arrow keys back to the arena.

3 Learn the concept

Stage, Scene, root

  • A Stage is the window, which you receive in start(Stage stage).
  • A Scene holds everything shown in the window. It has exactly one root, such as a VBox or BorderPane.
  • A node can be in only one place at a time. A root can belong to only one Scene. If you reuse a root in a second Scene, JavaFX throws an IllegalArgumentException saying it "is already set as root of another scene".

Three ways to change what the user sees

TechniqueCodeUse when
A. Switch scenesstage.setScene(gameScene);Screens are completely different, such as a menu vs. gameplay. This is the clearest choice for this skill.
B. One scene, swap its rootscene.setRoot(gameRoot);Same idea as A, but the window keeps one Scene object. Handy when you want the window size to follow one scene.
C. Change content inside one layoutroot.setCenter(otherPane); or label.setText(...)Most of the screen stays the same, such as the header and buttons, and only one region changes. This is not a new screen.

A welcome screen is a small layout

Label title = new Label("Drone Arena");
Button play = new Button("Play");
VBox welcome = new VBox(16, title, /* instructions, */ play);
welcome.setAlignment(Pos.CENTER);           // import javafx.geometry.Pos
play.setOnAction(event -> { /* show the game; give the arena focus */ });

When are multiple screens a good idea?

Good reasons

  • Different modes with different controls: menu, play, results, settings
  • The user moves between them on purpose
  • Mixing them on one screen would be crowded or confusing

Probably not needed

  • Showing a message: use a Label
  • One small choice: use a ComboBox (Skill 06)
  • Information shown next to the main view: use a BorderPane region
  • "It looks more professional." Get the core working first.

Not a game? How this transfers
  • Math solver: a home screen where the user picks a problem type (linear, quadratic, unit conversion) and each solver screen has a Back button.
  • Utility: a list screen and a detail/edit screen. Coming back should show the updated list, so you preserve state.
  • Quiz: start → question → results. "Try again" is a reset.

5 Design before coding

  1. Screens: sketch each screen and the buttons that move between them, as boxes and arrows.
  2. Build once or rebuild? If you build the game scene once and reuse it, everything is preserved: drone position, orb, and level. If you build a new one every time, everything starts fresh. Which do you want? You can also reuse it and call your reset code.
  3. What pauses? When the player leaves the game, what should happen to the Timeline?
  4. References: the Play handler needs the game scene, and the Menu handler needs the welcome scene. Will you keep them as local variables inside start or as fields? (See the hint in Step 4.)
  5. Readability: start is already long. Would helper methods such as buildWelcomeView() and buildGameView() that each return a Parent make it easier to read?

6 Guided implementation

  1. Name the game scene. Replace stage.setScene(new Scene(root, 640, 400)); with a variable, such as Scene gameScene = new Scene(root, 640, 400);, followed by stage.setScene(gameScene);.

    Check: nothing changes when you run. This is a safe first refactor.

  2. Build the welcome layout. Create a title Label, a one-line instructions Label, and a Play Button inside a VBox, centered with setAlignment(Pos.CENTER). Wrap it in a Scene of the same size.
    Optional: bigger title text

    title.setStyle("-fx-font-size: 32px; -fx-font-weight: bold;"); uses JavaFX CSS on one node. It is optional, and you do not need a stylesheet file.

  3. Open on the welcome screen. Call stage.setScene(...) with the welcome scene instead of the game scene.
  4. Play shows the game. In the Play handler, switch the stage to the game scene, then call canvas.requestFocus().
    Hint: "variable might not have been initialized"

    A lambda can use a local variable only if the variable already has its value and never changes (it is "effectively final"). Create both scenes first, then call play.setOnAction(...) and menu.setOnAction(...), or store the scenes in fields. You can register a handler at any time after the button exists.

    Check: Play opens the arena, and the arrow keys work right away without a click.

  5. Add a Menu button. Add it to the controls VBox. Its handler should follow your Step 5 decision: stop or pause flight, then show the welcome scene.
  6. Decide preserve vs. reset, on purpose. Reusing the same game scene preserves state. To make Play start fresh instead, have it run the same reset logic as the Reset button. If you did Skill 02, that is loadLevel(...). Avoid copying those lines into a second place.

7 Test your skill

  • NormalThe app opens on the welcome screen. Play shows the arena, and the arrow keys work immediately. All Lab 15 controls still work.
  • EdgePress Menu while the drone is flying: the welcome screen appears and the drone does not keep moving in the background. (Wait a few seconds, return, and check its position.) Press arrow keys on the welcome screen: nothing breaks.
  • Repeat / resetPlay → Menu → Play five times: state is preserved or reset exactly as you designed, the speed never increases, and the window size never changes.

8 Extend the skill

Challenge: a results screen that receives data

When the orb (or the last level) is collected, switch to a third screen that shows a result such as "Collected in 4.2 seconds" or your score from Skill 04. It should have Play again and Menu buttons. The design question: how does the results screen get the value? Consider a method like showResults(int score) that updates a results Label before switching scenes.
