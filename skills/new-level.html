Skill 02: Add a New Level

Describe each level as data, keep track of the current one, and reset cleanly when the next level begins.

  • CategoryGame mechanics and levels
  • DifficultyIntermediate
  • ConceptsData class, ArrayList, current index, loadLevel, Rectangle obstacle
  • PrerequisitesLab 15, ArrayList
  • EffortAbout 1.5–3 hours

1 Mission

Lab 15 has exactly one challenge: collect one orb, then press Reset. Real games progress. After the orb is collected, the next level should load, with the orb in a new place and maybe a wall in the way. After the last level, the player wins.

Your mission: add at least two more levels to the Drone Arena, without copying the whole game for each one.

Why you might need this: game stages, quiz rounds, practice sets of increasing difficulty, or simulation scenarios that each start from different settings.

2 What you already know

  • Classes and objects: a class with private fields, a constructor, and getters, as in Lab 09 and Lab 10.
  • ArrayList: add, get(index), size(), and indexes that start at 0.
  • Lab 15: the orb is a Circle moved with setCenterX/Y, collected with getBoundsInParent().intersects(...), hidden with setVisible(false), and restored by Reset.
  • Lab 12: a reset puts all related state back. Forgetting one piece causes "stale state" bugs.

3 Learn the concept

What defines a level?

A level is the set of values that differ from one stage to the next. The rules usually stay the same: steer, avoid walls, collect the orb. Only the numbers change.

Changes per level (data)

  • Orb position
  • Wall position and size
  • Level name or message
  • Maybe the drone's start, speed, or a time limit

Stays the same (code)

  • How the drone moves
  • How collision is detected
  • What collecting an orb means
  • How the display is updated

Separate level data from display logic

Put the data in a small class with no JavaFX imports. The JavaFX code reads that data and positions the shapes. To add a level, you add one line of data and no new game code.

Shape of a level class (fill in the rest) 
/** Everything that is different between levels. No JavaFX here. */
public class Level {
    private final String name;
    private final double orbX;
    private final double orbY;
    // TODO: wall x, y, width, height (or whatever your levels need)

    public Level(String name, double orbX, double orbY /* , ... */) {
        // TODO
    }

    public double getOrbX() { return orbX; }
    // TODO: the other getters
}
The levels themselves are just data 
levels.add(new Level("Level 1: Warm-up", 390, 205 /* , no wall */));
levels.add(new Level("Level 2: The Wall", 440,  60 /* , wall values */));

Track the current level and load it in one place

Reuse nodes. Don't re-add them. Add the orb and the wall to canvas once, then move them in loadLevel. If you call canvas.getChildren().add(...) every time a level loads, you get duplicate shapes. Adding the same node twice throws IllegalArgumentException: Children: duplicate children added.

Not a game? How this transfers
  • Quiz app: a QuestionSet or Round class holds the questions for one round, with a current-round index and a loadRound(i) that clears old answers and score-for-round.
  • Math practice: difficulty tiers, with each tier storing the ranges for random coefficients.
  • Simulation: preset scenarios (starting population, rates). Loading a scenario resets the model and the display.

5 Design before coding

  1. Data: list every value that differs between your levels. Those become the fields of Level. Anything else stays as code.
  2. Ownership: who owns the list of levels and the current index? (ArrowApp is fine for a small app. A Game or LevelManager class is cleaner if ArrowApp is getting long.)
  3. Reset list: write down everything that must return to its starting value when a level begins. Look at the Reset handler and the status label, and think about score if you have done Skill 04.
  4. Transitions: what happens after the last level? What happens if the drone hits a wall: restart the level, lose a life, or just stop?
  5. Reset vs. New Game: should Reset restart the current level or go back to Level 1? Many games offer both.

6 Guided implementation

  1. Create Level.java in the same package as ArrowApp. Use only the fields from your design: private and final, with a constructor and getters. No JavaFX imports.

    Check: it compiles. Nothing visible changes yet.

  2. Store the levels. In ArrowApp, add a field private final List<Level> levels = new ArrayList<>(); (import java.util.List and java.util.ArrayList). Add your levels at the start of start(...). Make Level 1 match Lab 15's orb at (390, 205).
  3. Track the current level with an int field that starts at 0. Add a Label for the level name to the header HBox.
  4. Write loadLevel. Start from what the Reset handler already does, then add the level data: 
    private void loadLevel(int index, SceneToken token, Label status) {
    // 1. stop the Timeline
    // 2. remember index as the current level
    // 3. Level level = levels.get(index);
    // 4. reset the drone
    // 5. move the crystal to the level's orb position; make it visible
    // 6. move/resize the wall (or hide it if this level has none)
    // 7. update the level label and status
}
    Hint: why pass token?

    token is a local variable inside start, so other methods cannot see it unless you pass it in or make it a field. checkCollision already uses the parameter approach.

  5. Use loadLevel everywhere a level starts. Call loadLevel(0, token, status) near the end of start, before stage.show(). Replace the body of the Reset handler with a call that reloads the current level, and keep canvas.requestFocus().

    Check: the app looks like Lab 15 and the level label shows Level 1. Reset still works.

  6. Advance after collecting. In checkCollision, after the orb is hidden, decide: if there is a next level, load it. Otherwise, show a win message.
    Hint: the boundary condition

    With 3 levels, the indexes are 0, 1, 2. "There is a next level" means currentLevel + 1 < levels.size(). Test this with the last level, where an off-by-one error causes IndexOutOfBoundsException.

    Check: collect the orb on Level 1, and Level 2 loads with the orb in a new place.

  7. Add an obstacle. Create one Rectangle wall field, add it to canvas once (it can go in the Pane constructor's child list), and set its x, y, width, and height in loadLevel. In checkCollision, test the drone against wall.getBoundsInParent(), the same way as the orb. Choose the consequence from your design.
    Hint: a hidden wall still has bounds

    Just like the orb in Lab 15, an invisible node still takes up space. Check wall.isVisible() before you treat contact as a crash.

7 Test your skill

  • NormalCollect the orb on Level 1: Level 2 loads, the drone is back at its start, the orb is visible in a new place, and the label says Level 2. Finish every level in order.
  • EdgeCollect the orb on the last level: a win message appears and nothing crashes. Fly into the wall from each side. Rotate into the wall.
  • Repeat / resetPress Reset in the middle of Level 2: you stay on Level 2. Replay a level five times, then temporarily print canvas.getChildren().size(). The number must not grow.

8 Extend the skill

Challenge: levels from a file

Move the level data out of Java code and into a text file such as levels.txt, one level per line: Level 2,440,60,320,0,20,200. Read it with a Scanner when the app starts and build the Level objects from each line. Designers can then add levels without touching Java. See Working with Files, and decide what happens when a line is malformed.
