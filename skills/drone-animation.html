1 Mission

In your finished Lab 15 app, each arrow-key press moves the drone 10 pixels. If you hold a key, the drone jumps once, waits, and then stutters. That pattern comes from your computer's key-repeat setting, not from your code. Meanwhile, Start moves the drone smoothly, because the Timeline moves it a little every 20 milliseconds.

Your mission: combine the two. The drone should glide while an arrow key is held and stop the moment you let go. It should also pause and resume, reset cleanly, and never leave the arena.

Why you might need this: player movement in real-time games, objects drifting in a simulation, or a visualization that animates one step at a time.

2 What you already know

  • Lab 12: a field keeps its value between events. A local variable inside a handler starts over every time.
  • Lab 13: one Timeline with a 20 ms KeyFrame calls token.step(...) again and again. play() starts it, stop() stops it, and the optional Pause step used pause().
  • Lab 15: setOnKeyPressed and event.getCode() pick a direction, and token.moveBy(...) keeps the drone inside all four edges.
  • Java: if / else if chains, double fields, getters and setters.

3 Learn the concept

Event-driven vs. time-driven change

An event happens once, such as a key going down, a key coming up, or a click. A tick happens again and again on a clock. Continuous movement uses both. Key events change what the drone intends to do. Ticks change where the drone actually is.

Velocity is just two fields

Velocity is how many pixels to move on each tick. The value 3 matches Lab 13's SPEED. Positive x moves right. Positive y moves down, because screen y grows downward.

Idea, not final code 
private double vx = 0;   // pixels per tick, left/right
private double vy = 0;   // pixels per tick, up/down

// on every tick:   move by (vx, vy)
// key pressed:     set vx or vy to the speed
// key released:    set that axis back to 0

A new event: key released

You already use setOnKeyPressed. JavaFX also has setOnKeyReleased, which runs once when a key comes back up. It works the same way: register a lambda, then read event.getCode().

canvas.setOnKeyReleased(event -> {
    KeyCode code = event.getCode();
    // which axis should stop?
});

One clock only. Do not add a second Timeline for the keys. Two clocks moving the same drone make movement depend on two timers, and bugs get hard to reproduce. Put everything that changes per tick in the one KeyFrame callback.

Controlling the Timeline

  • flight.play() starts the Timeline, or resumes it after a pause. Calling it while it is already running does nothing, so it does not speed up.
  • flight.pause() freezes it. The next play() continues.
  • flight.stop() stops it. Stopping does not move the drone back. Your token.reset() does that.
  • flight.getStatus() == Animation.Status.RUNNING tells you whether it is running right now. This needs import javafx.animation.Animation;.

Not a game? How this transfers
  • Simulation: the Timeline is your clock. Each tick calls a tick() or step() method on your model, such as moving particles or growing a population. A Step button can call the same method once, which makes testing easy.
  • Algorithm visualization: each tick performs one step, such as one swap in a sort, and redraws. Pause and Reset work exactly as above.
  • Math apps: you often do not need animation. A Step button, or updating as the user types, is usually clearer.

6 Guided implementation

Work on a branch. Run the app after every step, and close the window before running javafx:run again.

  1. Add velocity state to SceneToken. Declare two private double fields that start at 0. They change during the game, so they are not final or static, unlike SPEED.

    Check: the project still compiles and behaves exactly like Lab 15.

  2. Give SceneToken methods to set velocity and to move one tick. One setter per axis works well, because pressing Up should not cancel Right. Then add a tick method: 
    /** Move one tick using the current velocity; stay inside the arena. */
public void tick(double width, double height) {
    // TODO: reuse moveBy(...) so keepInArena(...) still runs
}
    Hint

    Your tick method should contain a single call to an existing method. If you find yourself copying the bounds code from keepInArena, stop and reuse it.

  3. Make the Timeline apply velocity. In ArrowApp.start(...), edit the KeyFrame callback so each tick calls your tick method with canvas.getWidth() and canvas.getHeight(). Keep checkCollision(token, status) after the movement. Use your Step 5 decision to decide what happens to token.step(...).

    Check: Start runs with no visible change yet, because velocity is still 0. Collection still works if you nudge into the orb.

  4. Pressing a key sets velocity. In canvas.setOnKeyPressed, change each direction so it sets velocity instead of calling moveBy(±10, ...). Here is one branch: 
    if (code == KeyCode.RIGHT) {
    token.setVelocityX(/* positive speed */);
}
// LEFT, UP, DOWN: which sign, which axis?

    Keep the existing block at the end that calls checkCollision and event.consume().

  5. Releasing a key stops that axis. Register canvas.setOnKeyReleased(...) right after the pressed handler. LEFT or RIGHT clears horizontal velocity, and UP or DOWN clears vertical.

    Check: Start, hold Right, and the drone glides. Let go, and it stops. Hold Up and Right together, and it moves diagonally.

  6. Add Pause. Create a Button named Pause, add it to the controls VBox, and in its handler call flight.pause() and then canvas.requestFocus(). Start's existing play() already resumes.
    Why requestFocus?

    Clicking a button gives the button keyboard focus. Without canvas.requestFocus(), the arrow keys go to the button and not to your arena. Lab 15 does this in every handler for the same reason.

  7. Make Reset clear velocity. Set both velocity fields to 0 inside SceneToken.reset(). The Reset button already calls it, so you do not need to change ArrowApp.
  8. Keep the old controls working (your Step 5 decision). If arrows should still nudge while stopped or paused, check flight.getStatus() == Animation.Status.RUNNING in the pressed handler. Set velocity when it is running, and call the existing moveBy(±10, ...) when it is not.

    Check: Pause, then tap Left, and the drone moves 10 pixels. Press Start and hold Left, and it glides.

8 Extend the skill

Mini-challenge: fly where you face

Change how Start's flight behaves without breaking the arrow keys or Reset. The drone should fly forward in the direction it is facing, so Rotate steers it.

  • The angle lives in SceneToken's turn field. Read it with turn.getAngle() in degrees, and convert it with Math.toRadians(...).
  • One tick forward moves SPEED * Math.cos(angle) in x and SPEED * Math.sin(angle) in y. Because screen y points down, positive JavaFX angles turn clockwise, so 90° means "down".
  • Predict, then test: Rotate six times (90°) and press Start. Which way should the drone go?

Harder challenge: overlapping keys

Fix the edge-case test: holding Left while pressing and releasing Right should keep moving left. Keep a Set<KeyCode> (for example, a HashSet) of keys that are currently held. Add on press, remove on release, and work out velocity from the set on every tick.
