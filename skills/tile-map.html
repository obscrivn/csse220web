Skill 10: Build a Tile Map from a Text File

Draw your map in a text editor, one character per tile. Turn it into a grid, a start position, and game objects, then draw it on screen.

  • PrerequisitesSkill 05, Skill 09

1 Mission

In Skill 05, the grid is an int[][] typed into Java code. That works for one small map, but a maze with ten rows is hard to read as numbers, and every change needs a recompile. Game designers draw maps as text, where each character is one tile, so you can see the maze in the file.

Your mission: load a maze from maps/map1.txt. Walls, floor, the drone's start, and the orbs all come from the file. The app checks the map for mistakes, sizes the tiles to fit the arena, and lets the drone move through it one cell at a time.

2 What you already know

  • Skill 05: cells[row][col], row/col ↔ x/y with a tile size, drawing tiles with nested loops, and a GridWorld model with tryMove.
  • Skill 09: reading every line of a file in src/main/resources with getResourceAsStream and Scanner, and error messages that say where the problem is.
  • Strings: length() and charAt(i); char comparisons such as c == 'W'.

3 Learn the concept

A map file is a picture made of characters

src/main/resources/maps/map1.txt 
WWWWWWWWWW
WD...W..OW
W.WW.W.W.W
W..W...W.W
W.OW.W...W
WWWWWWWWWW
CharMeaningBecomes
WWallA blocked cell, drawn dark
.FloorAn open cell
DDrone startFloor, plus the start row and column
OEnergy orbFloor, plus an orb object in that cell

The legend is your design. A board game might use R and B for pieces; a seating chart might use S for seats.

Text → grid: line number is the row, character position is the column

char[][] tiles = new char[lines.size()][cols];
for (int row = 0; row < lines.size(); row++) {
    String line = lines.get(row);
    for (int col = 0; col < cols; col++) {
        char c = line.charAt(col);
        // TODO: remember the start if c is 'D'; remember an orb cell if c is 'O';
        //       reject any character that is not in your legend
        tiles[row][col] = c;
    }
}

Check the map before you trust it

A map with a typo can put the drone inside a wall or leave a row short, which causes an ArrayIndexOutOfBoundsException later, far from the real mistake. Check the map once, while loading, and report the exact spot. These are the real messages from a working map loader:

Row 1 has 2 tiles, but row 0 has 3
Unknown tile 'X' at row 0, col 2
The map has no D (drone start)
More than one D (row 0, col 1)
The map has no O (orb)
The map is empty

Make the tiles fit the arena

The Lab 15 arena is 500 × 300. Choose the tile size from the map instead of hard-coding it, so a bigger map gets smaller tiles:

double tile = Math.min(500.0 / map.getCols(), 300.0 / map.getRows());   // 10 x 6 map → 50

A 90-pixel drone does not fit in a 50-pixel tile. Give SceneToken a second constructor that takes the size, and keep the old one working:

public SceneToken() {
    this(90);                       // Lab 15 behavior is unchanged
}

public SceneToken(double size) {
    // same body as before, but use size instead of 90,
    // and put the rotation pivot at size / 2
}

Not a game? How this transfers
  • Puzzle or math: a Sudoku file, with digits for givens and . for empty cells, loaded into a grid that a solver checks.
  • Recursion visualizer: a maze file plus a recursive path finder that colors the path it finds, connecting to the course's recursion unit.
  • Simulation: a starting pattern for Conway's Game of Life, with # for alive and . for dead.
  • Utility: a room layout or seating chart, where each character is a seat, an aisle, or a desk.

5 Design before coding

  1. Legend: list every character and what it becomes: a tile type, an object, a position, or several of these.
  2. Rules: what makes a map invalid? (Rows of different lengths, unknown characters, the wrong number of starts, no goal.)
  3. Responsibilities: one class (for example, TileMap) reads and checks the characters, with no JavaFX. Does GridWorld still own movement? Which class draws the tiles?
  4. What's under an object? D and O cells are floor once the drone or orb is recorded. Should isWall return true or false for them?
  5. Size: what is the largest map you want to support before tiles get too small to see?

6 Guided implementation

  1. Draw the map. Create src/main/resources/maps/map1.txt, as in Skill 09. Make sure every orb can be reached from D. Trace a path with your finger before you write any code.
  2. Create TileMap (no JavaFX) with a char[][], the start row and column, and a list of orb cells. Add a static method fromLines(List<String> lines) that fills them with the loop above. Add getRows(), getCols(), getTile(row, col), isWall(row, col), and getters for the start and orbs.
    Hint: storing an orb cell

    new int[] {row, col} stores both numbers in one small array, and a List<int[]> holds all of them. A tiny Cell class with row and col fields is clearer, if you prefer.

  3. Validate while you read. Compare every line's length with the first line's. Reject characters that are not in your legend. After the loop, require exactly one D and at least one O. Each message says the row and column.
  4. Check it without the GUI with a TileMapCheck class (the Skill 04 pattern). Feed it tiny maps with List.of("WWWWW", "WD.OW", "WWWWW"), check the start and orb positions, and feed it each broken map from Step 3.

    Check: every line prints PASS, including the broken maps.

  5. Load from the file. Add TileMap.load("/maps/map1.txt"), which reads the lines (Skill 09), skips blank ones, and calls fromLines. In ArrowApp.start, load inside try and show the message in a Label if it fails.
  6. Size the drone. Add the SceneToken(double size) constructor and create the drone at about 80% of a tile.

    Check: Lab 15 code that still calls new SceneToken() looks exactly as before.

  7. Draw the map. Compute tile, then use a nested loop to add one Rectangle per cell, colored by its character. Add one Circle per orb cell, at the center of that tile. Add the drone last, so it is drawn on top.

    Check: the screen matches the text file character for character. Compare one row at a time.

  8. Connect movement. Build the Skill 05 GridWorld from the map: a method like toGridLayout() turns W into WALL and everything else into OPEN, and the start comes from D. Use the same arrow-key code and placeAt helper as Skill 05, with an offset that centers the smaller drone.
  9. Collect and reset. When the drone enters an orb's cell, hide that orb, and show how many are left. Reset returns the drone to D and shows every orb again.

7 Test your skill

  • NormalThe drawn maze matches the file exactly. The drone starts on D, walls block it, and walking a path collects every orb.
  • EdgeEdit the file to break it: a short row, an X, two Ds, no O. Each shows a clear message, and nothing crashes. Then try a valid map of a different size (for example, 8 × 4): the tiles resize and everything still fits the arena.
  • Repeat / resetCollect some orbs, then press Reset: all orbs return, and the drone is back on D in both the model and the view. Change only the map file, rerun, and play the new maze with no Java edits.

8 Extend the skill

Challenge: a sequence of maps as levels

Add map2.txt and map3.txt. When every orb on a map is collected, load the next map, combining this skill with Skill 02. Because the tile size is computed from each map, maps can be different sizes. Make sure the old tiles and orbs are removed from the canvas first, as in Skill 09. For a bigger challenge, add a new legend character, such as H for a hazard that sends the drone back to D.
