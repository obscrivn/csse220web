GitHub Desktop guide for Milestone 1

This guide is for beginners using GitHub Desktop with a shared CSSE220 final-project repository. The goal is to practice the safe team workflow without touching main directly.

1. One-time setup

  1. Make sure you have a GitHub account and GitHub Desktop installed.
  2. Sign in to GitHub Desktop using the same GitHub account used for the team repo.
  3. Confirm the team setup lead created the repository and invited you as a collaborator.
  4. Choose a project folder that is not already a Git repository.

2. Clone the team repository

  1. Open GitHub Desktop and choose File → Clone repository.
  2. Select the correct shared repository, or paste the repository URL.
  3. Choose a local folder and click Clone.
  4. Open the project in your IDE.

3. Create a branch

  1. Check the current branch name.
  2. Click Current Branch and choose New Branch.
  3. Use a descriptive name such as alex-project-pitch or sam-uml.
  4. Base the branch on the current main branch.

4. Make a small, independent change

Pick one file to edit. Good examples:

  • docs/idea.md
  • docs/design.md
  • docs/team-plan.md

Then open GitHub Desktop in the repository and check the changed files before committing.

5. Commit locally

  1. Review the changed files.
  2. Write a meaningful message like Add project idea draft.
  3. Click Commit to [branch].
Important: commit is a local saved snapshot. It does not upload your work to GitHub.

6. Push the branch

  1. Click Publish branch or Push origin.
  2. GitHub Desktop uploads the branch to the shared repository.
  3. Your teammates can now review the branch on GitHub.

7. Open a pull request

  1. Choose Create Pull Request.
  2. Set the base branch to main and the compare branch to your feature branch.
  3. Write a short explanation of the change and why it matters.
  4. Ask a teammate to review it.

8. Review and merge

  1. Another teammate opens the pull request and checks the files.
  2. If the work is correct, the reviewer merges it into main.
  3. If the content is unclear or there is a conflict, stop and ask the instructor or team lead.

9. Sync local main

  1. Switch back to main.
  2. Click Fetch origin or Pull origin.
  3. Now your local repo is up to date with the merged version.
  4. Create the next feature branch from updated main.

10. Common problems

  • Invite not visible: accept the GitHub repository invite and refresh GitHub Desktop.
  • Branch not appearing: make sure it is based on the correct repository and the current branch is set correctly.
  • No changes to commit: confirm the file saved and includes the expected edits.
  • Merge conflict: do not discard changes; ask for help before doing anything risky.
Safety reminder: never commit directly to main, never force-push, and never delete the repository's hidden Git files to try to fix a problem.

11. Core vocabulary

  • Commit = a local save point.
  • Push = upload local commits to GitHub.
  • Pull request = request to merge a feature branch into main.
  • Pull = update your local branch with the latest remote changes.
