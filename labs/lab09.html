Lab 09

🎮 Arena Player System

The Player class is broken. Can you fix the design?

You are working on a small arena game. The previous developer left behind a UML diagram, but some important design information is missing. Your job is to figure out what belongs to each player, what should be shared by all players, and what should not be changed directly from outside the Player class.

Learning goals
  • Tell the difference between private, static, and final.
  • Decide what belongs to one object and what is shared by every object of a class.
  • Read a UML diagram and create Java classes and an interface from it.
  • Use methods to safely change an object, then check that the program works.

Part 1: 🔎 What’s Wrong with This Design?

Study the broken UML image before you write any code. It shows the names of the pieces, but not the access or scope choices.

  1. Which fields should belong separately to each Player?
  2. Is playerCount different for each Player, or should all Players share it?
  3. Should MAX_HEALTH ever change while the program is running?
  4. Should another class be able to directly change a Player’s health or score?
  5. What does Player implements Healable mean?

Checkpoint: Make your predictions first. Then ask an instructor or TA to review one decision before you start coding.

Part 2: 🛠️ Build It

Create a Java project in IntelliJ. See Lab08 how to create a new package.

Required package name: lab
In the src folder, create a package named exactly lab. Every Java file in this lab must begin with package lab;. The autograder expects this package name.

src/
└── lab/
    ├── Healable.java
    ├── Player.java
    └── GameApp.java
  1. In IntelliJ, create a new Java project using Java 21.
  2. Create the lab package inside src.
  3. Create new Java classes: Healable.java, Player.java, and GameApp.java in the lab package.
Your design needs to support these requirements
  • Each player has a name, health, level, and score.
  • Creating a new player increases the total number of players, and the program can find that total.
  • Every player has the same maximum health of 100, and that maximum does not change while the program runs.
  • A player’s health and score change only through appropriate Player methods.
  • Health cannot drop below 0 or increase above the maximum.
  • Player implements Healable, which declares void heal(int amount).

Use what you have learned about private, static, final, instance fields, and interfaces to choose the design.

Part 3: 🎮 Make the Player Work

New Player

Store the name. Start at level 1, score 0, and full health. Creating a Player increases the total number of players.

Score

addScore adds points to that Player’s score.

Damage

takeDamage reduces health but never lets health go below 0.

Healing

heal restores health but never lets it go above the maximum.

Keep the challenge focused: Use the requirements to decide what belongs to one Player, what belongs to all Players, what can change, and what outside code should be allowed to change.
