Step 7: Create the Collidable Interface

Create an interface named Collidable. 

public interface Collidable {
    boolean collidesWith(Collidable other);
}

This lets different game objects share the same collision behavior later.

Step 8: Make Ball Collidable

Update the Ball class so it implements Collidable. 

public class Ball implements Collidable {
    // fields and methods
}

Then implement collidesWith. 

public boolean collidesWith(Collidable other) {
    Ball otherBall = (Ball) other;
    return this.getBounds().intersects(otherBall.getBounds());
}

The method uses Collidable as a parameter so it can accept any object that can collide, not just a Ball.

This makes the code more flexible. Later, we could add other objects like players, enemies, or walls, and they could all use the same method.

However, inside this method we need access to Ball. That is why we use casting: 

Ball otherBall = (Ball) other;

The method intersects is built into Java's Rectangle class. It returns true if two rectangles overlap.

Step 9: Update All Moving Objects

In GameModel, the update method should move the player and the balls. 

public void update() {
    if (player != null) {
        player.update();
    }

    for (Ball b : balls) {
        b.update();
    }

    // collision logic goes below
}

Think of update as one frame of the game: move first, then check collisions.

Step 10: Reverse Ball Direction When Balls Collide

Add a method in Ball that reverses its movement direction. 

public void reverse() {
    dx = -dx;
    dy = -dy;
}

Then check each pair of balls in GameModel in the update(). 

for (int i = 0; i < balls.size(); i++) {
    for (int j = i + 1; j < balls.size(); j++) {
        Ball a = balls.get(i);
        Ball b = balls.get(j);

        if (a.collidesWith(b)) {
            a.reverse();
            b.reverse();
        }
    }
}

The j = i + 1 part prevents checking the same pair twice.

Step 11: Remove Balls When the Player Touches Them

If the player collides with a ball, remove that ball from the list.

When removing from an ArrayList, looping forward is not safe because the list shifts after a removal.

When you remove an element, all elements to the right move one position left. This changes the indices while your loop is still running.

To avoid this, loop backwards so index shifting does not affect the remaining elements you still need to check. 

//  Safe (backward loop)
for (int i = balls.size() - 1; i >= 0; i--) {
    if (player.collidesWith(balls.get(i))) {
        balls.remove(i);
    }
}

This makes the ball disappear from the game world.

Step 12: Final Update Structure

Your update method should follow this order:

  1. Update the player
  2. Update the balls
  3. Reverse balls that collide with each other
  4. Remove balls that collide with the player

Design Check

The Ball class knows how to detect its own collision. The GameModel decides what happens when objects collide.

This keeps object knowledge inside the object and game rules inside the model.
