Turn Friday's arrow into a drone: display an image, fly right, stop at the wall, and reset. You will use these same skills in the JavaFX final project.

  3. Choose View → Tool Windows → Maven → Execute Maven Goal. Enter javafx:run.

1Display the image

Step 1a: Add image imports

File: SceneToken.java · Method/location: imports; outside all methods · Find: No TODO here: add imports above the class declaration.

Image holds pixels; ImageView displays them. Add:

import javafx.scene.image.Image;
import javafx.scene.image.ImageView;

Step 1b: Display the drone

File: SceneToken.java · Method/location: SceneToken() constructor · Find: TODO 1: replace these shapes with ONE ImageView of /images/drone.png.

Replace shaft/tip creation through view = new Group(shaft, tip); with:

Image image = new Image(SceneToken.class
        .getResource("/images/drone.png").toExternalForm());
ImageView drone = new ImageView(image);
drone.setFitWidth(90);
drone.setPreserveRatio(true);
view = new Group(drone);

Keep the following transform registration and reset() call. Load the image once, here.

Step 1c: Center the pivot

File: SceneToken.java · Method/location: turn field initializer; outside methods · Find: No TODO here: find private final Rotate turn = new Rotate(0, 30, 10);

Change the pivot to the center of the 90 × 90 display:

private final Rotate turn = new Rotate(0, 45, 45);

You should now see… the drone instead of the arrow. Rotate turns it about its center by 15°; Reset restores it. Complete 1a–1c together before running.

2Move one tick

Step 2: Move one tick

File: SceneToken.java · Method/location: step(double playWidth) · Find: TODO 4: increase translateX by SPEED.

Add this at the listed TODO 4 in SceneToken.step(). Keep the existing return false; until Step 4.

Predict: rotation does not appear in this calculation. Should turning affect travel direction?

You should now see… the same stationary drone when you run. This method is not called yet; no visible movement is expected until Step 3. Confirm the project still compiles.

3Animate the drone

Step 3a: Create one Timeline

File: ArrowApp.java · Method/location: start(Stage stage), before button handlers · Find: TODO 3: create ONE Timeline here, before registering handlers.

The field is already provided. Near the top of ArrowApp, outside start(), find:

private Timeline flight;

Keep this existing field. Do not add another field. At TODO 3 inside start(), assign to it using flight = new Timeline(...) as shown below; do not write Timeline flight = ..., which would create a separate local variable. The supplied imports are already present. A Timeline repeats its callback about every 20 milliseconds.

flight = new Timeline(new KeyFrame(Duration.millis(20), event -> {
    token.step(canvas.getWidth());
}));
flight.setCycleCount(Timeline.INDEFINITE);

Step 3b: Start flight

File: ArrowApp.java · Method/location: start(Stage stage), Start button handler · Find: TODO 4: play the existing flight and update status.

flight.play();
status.setText("Flying right");

You should now see… the drone move right after Start. Repeated Start clicks do not increase speed. Close the window before it leaves the play area; stopping comes in Step 4.

Create only one Timeline during setup; the callback runs repeatedly. Complete the callback’s arrival check later in HTML Step 4c; it is part of the original TODO 3 instructions.

4Stop at the right edge

Step 4a: Clamp the right edge

File: SceneToken.java · Method/location: keepInside(double playWidth) · Find: TODO 5: compare view.getBoundsInParent().getMaxX() to playWidth.

Read the rotated right edge in the play area’s coordinates. Complete the missing correction:

double rightEdge = view.getBoundsInParent().getMaxX();
double overflow = rightEdge - playWidth;
if (overflow > 0) {
    // Subtract overflow from translateX using setTranslateX(...).
}

If rightEdge is 503 and playWidth is 500, subtract 3 from translateX.

Step 4b: Report arrival

File: SceneToken.java · Method/location: step(double playWidth), after movement · Find: TODO 5: clamp via keepInside(playWidth), then report whether at the edge.

After the movement statement, call keepInside(playWidth). Replace return false; with:

return view.getBoundsInParent().getMaxX() >= playWidth - 0.001;

True means arrival; the tolerance allows rounding.

Step 4c: Stop on arrival

File: ArrowApp.java · Method/location: start(Stage stage), Timeline callback created in HTML Step 3a · Find: TODO 3: create ONE Timeline here, before registering handlers.

Return to the callback you created in HTML Step 3a, under the original TODO 3 instructions. There is no separate TODO 4c in the distributed ZIP. Replace the standalone step call with this branch; fill in both actions:

if (token.step(canvas.getWidth())) {
    // Stop flight.
    // Show an arrival message using status.setText(...).
}

You should now see… after 4a–4c, the drone stops fully inside the right edge on Start. Reset its position between runs; Reset will stop active flight only after Step 5.

Example prompt:

Create one original friendly voxel drone sprite for a JavaFX game. Its front faces right, with a bright camera and slight asymmetry so rotation is visible. Use a simple silhouette readable at 90 pixels wide. Output a square 512 × 512 PNG with a genuinely transparent background, the entire drone visible, and minimal empty padding. No scenery, text, logos, or copied game textures.

Inspect → refine → test: check the downloaded file for real transparency, cropping, direction, and readability at 90 pixels. Refine one problem at a time: “Keep the design; remove the empty border and preserve transparency.” A painted checkerboard is not transparency.

Bundle your final PNG under resources. If its displayed size is not square, adjust the pivot to half its displayed width and height. Follow the course AI-use/help-citation policy.

HelpIf something goes wrong
  • Missing image: check src/main/resources/images/drone.png, exact capitalization, and lookup /images/drone.png. Reload Maven and rerun javafx:run. Avoid paths into Downloads.
  • Image behind background: keep the token Group last in the canvas child list.
  • Wrong size/pivot: fit width 90, preserve ratio, pivot (45,45).
  • No movement: check Start calls play, cycle count is INDEFINITE, and the callback calls step.
  • Reset keeps moving: stop the Timeline before resetting the token.

Skills you practiced

  • Asset design: describe a sprite's purpose, perspective, direction, transparency, and displayed size in a prompt, then inspect the result.
  • Portable resources: place a PNG under src/main/resources and load it with a classpath path that works beyond your computer.
  • JavaFX images: distinguish Image pixel data from an ImageView node; control displayed size and aspect ratio.
  • Object responsibilities: let SceneToken own its visual Group and transformations while ArrowApp connects controls and animation.
  • Animation: separate setup from repeated callbacks and reuse one Timeline for Start, stop, and restart.
  • Coordinates and state: keep rotation independent of horizontal movement, clamp rotated bounds to the play area, and reset position, angle, and animation together.
  • Verification: predict a speed change, test edge cases, explain behavior, and verify each student's implementation.
