Lab 12: Treasure Clicker

Build a counter that responds to you

Your treasure chest is on screen, but it does not respond yet. Make its buttons collect gold, share one total, and reset the treasure.

10 points · Four quests · Optional visual feedback

Learning goals

  • Identify Application, Stage, Scene, and VBox in a working JavaFX application.
  • Register button action handlers and explain when their code runs.
  • Keep state between events and update a Label with setText().
  • Reuse display-update behavior across several handlers.

Use your Java fields, methods, object-creation skills, and the JavaFX introduction demo. The project setup is provided.

SetupOpen the starter and run it Start here
  1. Download and extract Lab12.zip.
  2. In IntelliJ, choose Open and select the extracted Lab12 folder containing pom.xml.
  3. Trust the local project if prompted. Choose JDK 21 and let Maven import the dependencies.
  4. In Settings → Build, Execution, Deployment → Build Tools → Maven, use Bundled Maven. Under Maven → Runner, set JRE to Project JDK (21).
  5. Open View → Tool Windows → Maven. Choose Execute Maven Goal, select the Lab12 Maven root, and enter clean javafx:run.
  6. Open src/main/java/lab/TreasureApp.java. Find the gold field, controls, VBox, Scene, and Stage.

First check: the window opens with Treasure Clicker, Gold: 0, and Open Chest. Clicking the starter button does nothing yet.

Open the provided folder directly; do not create a new IntelliJ project. IntelliJ includes Maven. You do not need to install a JavaFX SDK.

Launch help
  • Use the Maven goal, rather than the plain Java gutter run action. Do not type mvn in IntelliJ's goal field.
  • In a terminal with Maven installed, run mvn clean javafx:run from the Lab12 folder.
  • If imports are red, reload Maven and check internet access. First import downloads dependencies.
  • If Java 21 is unsupported, check both Project SDK and Maven Runner JDK.
  • Close the running window before editing and relaunching.
Quest 1Collect Gold Required
  1. Predict: what should the gold total be after three Open Chest clicks?
  2. Find the Quest 1 TODO. Register an action handler on the provided openChest button.
  3. Make each activation add 10 to the existing gold field.
  4. Keep the total between events. Continue to Quest 2 to make the change visible.
Remember the callback

setOnAction registers a callback. A lambda such as event -> { ... } runs later when the button is activated. A counter initialized inside that callback would start over each time.

Quest 2Update the Display Required
  1. Implement updateDisplay(). Use the Label's setText() method to display Gold: followed by the current total.
  2. Call your helper after changing the total in the Open Chest handler.
  3. Run the app. Check Gold: 0 → Gold: 10 → Gold: 20 → Gold: 30 after three clicks.
  4. why does changing the integer field alone not change the label?

Check: every ordinary click changes both the total and the visible value. Close and relaunch; the new run starts at zero.

Quest 3Reset Treasure Required
  1. Create a Button labeled Reset and add it to the VBox.
  2. Register its action handler. Reset the shared total to zero and refresh the display.
  3. Test reset at zero, reset after collecting gold, and collecting after reset.

Check: 30 → Reset → 0 → Open Chest → 10. A second Reset at zero should still show Gold: 0.

Quest 4Upgrade the Chest Required
  1. Create another Button labeled Rare Chest and add it to the VBox.
  2. Register its handler. Award 25 gold to the same total and refresh the display.
  3. Predict, then test: Reset → Open Chest → Rare Chest → Rare Chest.
  4. Check that Reset clears treasure earned from either chest.

Check: the mixed-click sequence shows 0 → 10 → 35 → 60. Both chest buttons share one balance.

QualityKeep the handlers readable Required
  • Use meaningful variable names.
  • Keep each handler easy to read.
  • Reuse updateDisplay() so label formatting is not unnecessarily duplicated.

Other small helper-method designs are welcome. Choose an organization that makes each button's job clear.

BonusVisual Feedback Optional

After completing the four quests, add a Rectangle representing the chest.

  1. Choose two distinguishable colors.
  2. Use setFill() to change the chest color when the shared total reaches or exceeds 100.
  3. Keep the color consistent with the current total. Reset must restore the below-100 color.
  4. Test 90 → 100 with Open Chest, 95 → 120 with Rare Chest, and Reset afterward.

The rectangle provides visual feedback. No animation, mouse handler, external image, or CSS is required.

Optional: this bonus does not affect your 10-point base score.

Assessment: In-Class Verification

This lab uses instructor checkoff as the primary assessment.

Checkoff (10 points)

  1. Open Chest: three clicks produce 30 gold (3 pts).
  2. Reset: resets gold to zero (2 pts).
  3. Rare Chest: two clicks produce 50 gold (2 pts).
  4. Combined behavior: one additional regular click produces 60 gold (1 pt).
  5. Explain: event handling and label updates (2 pts).

Checkoff sequence: start a new run at zero → Open Chest three times (30) → Reset (0) → Rare Chest twice (50) → Open Chest once (60).

  1. Show your running app and Java source to the instructor/TA.
  2. Demonstrate the sequence above.
  3. Explain when the handlers execute and how setText() refreshes the label after state changes.
