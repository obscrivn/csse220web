Part 2: Interfaces: Your First Interface Hierarchy

In this lab you will write two Java interfaces and two classes that implement them. You will see how one interface can extend another interface, and how a class that implements the extended interface must satisfy the requirements of both interfaces.

Learning Goals

  • Define a Java interface and declare a method inside it.
  • Write a class that implements an interface.
  • Write a second interface that extends another interface.
  • Understand that extending an interface means inheriting its method requirements, not just adding new ones.
  • Write a class that implements an interface hierarchy and provides every required method.
  • Create objects and test their behavior from main.

No starter ZIP for this lab. You will create a brand-new plain Java project in IntelliJ just for Lab08, add a package named lab, and create each file yourself. You will test your code by running main and reading the output.

Part 1. Your First Interface Required

Resources: Interfaces

An interface describes behavior that a class promises to provide. It does not say how that behavior is implemented — only what methods must exist.

Step A: Create a new project

  1. Open IntelliJ IDEA.
  2. Choose File → New → Project... (or New Project from the welcome screen).
  3. Select Java as the language, and make sure the build system is set to IntelliJ, not Maven.
  4. Name the project Lab08, choose a location, and click Create.

Step B: Create the lab package

  1. In the Project window, right-click src.
  2. Choose New → Package.
  3. Name it lab. This is super important for gradescope autograder, pelase make sure you name it exactly as lab

Step C: Create the Rechargeable interface

  1. Right-click the lab package.
  2. Choose New → Java Class.
  3. Type Rechargeable as the name.
  4. In the list of kinds that appears (Class, Interface, Enum, Record, ...), choose Interface, then press Enter.
  5. IntelliJ creates the file with public interface Rechargeable { } already started. Add the one method signature shown below.
package lab;

public interface Rechargeable {
    void recharge(int amount);
}

💡 An interface has no method bodies and no fields of its own. Any class that says implements Rechargeable is promising to provide a working recharge(int amount) method.

Part 2. Implement an Interface Required

Next you will write a class that keeps its promise to Rechargeable.

  1. Right-click the lab package and choose New → Java Class. Type PowerBank as the name and leave the kind set to Class (the default), then press Enter.
  2. Declare it as public class PowerBank implements Rechargeable.
  3. Add two public fields: String name and int batteryLevel.
  4. Add a constructor PowerBank(String name, int batteryLevel) that uses this to set both fields.
  5. Implement recharge(int amount) so that it adds amount to batteryLevel.

Exact signatures required (these will be checked automatically):

package lab;

public class PowerBank implements Rechargeable {
    public String name;
    public int batteryLevel;

    public PowerBank(String name, int batteryLevel) {
        // TODO: use this.name and this.batteryLevel
    }

    public void recharge(int amount) {
        // TODO: increase batteryLevel by amount
    }
}

💡 PowerBank implements only Rechargeable. It does not need a getStatus() method, because Rechargeable never required one. Keep this in mind for Part 4.

Part 3. Extend an Interface Required

An interface can build on another interface using extends. This is different from a class extending a class — you are not creating a subclass, you are creating a bigger set of required methods.

  1. Right-click the lab package, choose New → Java Class, type SmartDevice as the name, and choose Interface from the kind list again.
  2. Declare it as public interface SmartDevice extends Rechargeable.
  3. Add one more method signature: String getStatus();
package lab;

public interface SmartDevice extends Rechargeable {
    String getStatus();
}

Key idea: because SmartDevice extends Rechargeable, any class that implements SmartDevice must provide the methods required by both interfaces, getStatus() and recharge(int amount).

💡 Compare the two lines carefully:
interface SmartDevice extends Rechargeable — one interface building on another interface.
class Robot implements SmartDevice (next part) — a class fulfilling an interface's contract.
At this point in the course, extends is only used between two interfaces. We are not creating subclasses.

Part 4. Implement the Extended Interface Required

Now write a class that implements SmartDevice. Because SmartDevice extends Rechargeable, this class must implement both required methods.

  1. Right-click the lab package, choose New → Java Class, type Robot as the name, and leave the kind set to Class, then press Enter.
  2. Declare it as public class Robot implements SmartDevice.
  3. Add two public fields: String name and int energy.
  4. Add a constructor Robot(String name, int energy) that uses this to set both fields.
  5. Implement recharge(int amount) so that it adds amount to energy.
  6. Implement getStatus() so that it returns exactly this format: 
    Robot: <name> (Energy: <energy>)
    For example, if name is "R2" and energy is 20, getStatus() must return the string Robot: R2 (Energy: 20).

Exact signatures required (these will be checked automatically):

package lab;

public class Robot implements SmartDevice {
    public String name;
    public int energy;

    public Robot(String name, int energy) {
        // TODO: use this.name and this.energy
    }

    public void recharge(int amount) {
        // TODO: increase energy by amount
    }

    public String getStatus() {
        // TODO: return "Robot: " + name + " (Energy: " + energy + ")"
        return null;
    }
}
💡 Optional: give your Robot one extra method

If you would like, add one small Robot-specific method of your own, such as move() that prints a short message. This is not required by any interface and is not graded — it is just a chance to make the class feel a little more like a robot.

Part 5. Test Your Objects Required

Create one more class, Lab08 (right-click the lab package → New → Java Class, kind Class), with a main method. This is how you will check your own work.

  1. Create a Robot.
  2. Print its status.
  3. Recharge it.
  4. Print its updated status and confirm the energy changed correctly.
  5. Create a PowerBank.
  6. Recharge it.
  7. Print enough information (its name and batteryLevel) to confirm its state changed.
package lab;

public class Lab08 {
    public static void main(String[] args) {
        Robot robot = new Robot("R2", 20);
        System.out.println(robot.getStatus());

        robot.recharge(15);
        System.out.println(robot.getStatus());

        PowerBank bank = new PowerBank("Anker", 50);
        System.out.println(bank.name + " battery level: " + bank.batteryLevel);

        bank.recharge(20);
        System.out.println(bank.name + " battery level: " + bank.batteryLevel);
    }
}
💡 Bonus: an interface-typed variable

A variable can be declared using an interface type. This is useful because it only exposes the methods that interface promises — nothing more. 

Rechargeable device = new Robot("Scout", 10);
device.recharge(10);

device can call recharge(...) because that is part of Rechargeable, but it could not call getStatus() through this variable, since Rechargeable does not require that method. This part is optional and not graded — try it if it matches what you have already covered in class.

Why this matters

This lab connects to a principle you have already seen in CSSE220: classes with similar features can share a common interface. Robot and PowerBank are different kinds of objects, but because they both implement Rechargeable, any code that only needs to recharge a device can work with either one through that shared interface, without caring which concrete class it actually is.
