Part 2: Inheritance: Treasure Hunt Gear

The sword and pickaxe repeat the same code. Move their shared state and behavior into Item, then give the sword its own action.

Learning Goals

  • Recognize duplicated state and behavior in related classes.
  • Create a superclass and inherit its fields and methods using extends.
  • Initialize shared state with super(...).
  • Override toString() and a subclass method with @Override.
  • Use a superclass reference to call a subclass's behavior.

B. Give items a useful string representation

Java classes inherit toString() from Object. Override it to describe your item when it is printed.

  1. In Item, add public String toString() with @Override.
  2. Return getDescription() to reuse the description you already have.
  3. Return a string; do not print inside toString().

Try it: after refactoring the subclasses, System.out.println(sword); will use the inherited toString() to print the item's description.

C. Refactor both subclasses

  1. Make Sword and Pickaxe directly extend Item.
  2. Keep each public (String name, int value) constructor.
  3. Use super(...) in each constructor to initialize shared state.
  4. Remove the repeated fields and four shared methods from both subclasses.

Check: run MainApp and RunAllTests. The output stays the same and all tests pass.

Keep these design rules
  • Store instance fields only in Item and keep them private.
  • Use getters when a subclass needs that data.
  • Keep the existing public signatures.
  • Assume non-null names and nonnegative values, including zero.
  • No abstract classes, interfaces, or extra hierarchy levels are needed.

Before You Submit

  • Sword and Pickaxe directly extend the concrete Item class.
  • Shared instance fields and shared methods appear only in Item.
  • Both subclass constructors initialize inherited state with super(...).
  • Item.toString() uses @Override and returns the item description.

  • All supplied and added tests pass; your final UML and reflections match your code.

Why this matters

Classes with similar internals can share state and implementation through inheritance. A superclass keeps the common work in one place, while a subclass can override a method to provide a more specific behavior. The relationship should also make sense: a sword and a pickaxe are both items.
