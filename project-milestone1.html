What you are building for this milestone

Do this now

  • Choose who will use your app and one useful thing they can do.
  • Sketch your main classes and explain what each one does.
  • Get the JavaFX starter running on every teammate’s computer.
  • Have each person share a small change using a branch and a reviewed pull request.
  • Submit a clear design summary and team plan.

Save this for later

  • More game/app features
  • Polished UI or animations
  • Multiple screens or levels
  • Testing, debugging, and final showcase

Work through these four steps

  1. Step 1: Define the user. State who the app is for, what problem it solves, and the first 30 seconds of the experience. Ask: What does the user do first? What should the app show immediately?
  2. Step 2: UML draft. Sketch your main classes, their fields and methods, and how they work together. Explain why you gave each class its responsibilities.
  3. Step 3: Starter and Git setup. Follow the GitHub walkthrough for your role. The lead sets up the shared repository first; invited teammates clone it. Everyone checks that the starter runs.
  4. Step 4: Branch workflow. Each person creates a branch and edits a different file. Save a commit, push it, and ask a teammate to review a pull request. Merge one PR at a time, then everyone pulls the updated main.

This milestone is about building an initial product direction and a working team process. You are not expected to finish a polished game yet.

Put your team’s plan in the shared document

Use the Google Docs template above. Talk through these questions together and write down your answers:

  1. Who is your app for? Give your project a title and describe its user.
  2. What happens first? Describe the user’s first 30 seconds: what they do and how the app responds.
  3. Which objects do you need? Start with three to five classes. Give each a clear job and include your UML sketch.
  4. Who is doing what next? List each teammate’s current task, file, and branch. Choose someone to review each change.

Share one small change each

Start with different files, such as docs/idea.md, docs/design.md, and docs/team-plan.md. You will create these during the exercise; they are not in the starter. This lets you practice sharing work without everyone editing StarterApp.java.

Create and switch branches in GitHub Desktop, then edit the files in IntelliJ. Review and merge pull requests on the GitHub website. Each person should be able to show their own commit and merged PR.

Follow the GitHub walkthrough for the buttons, review steps, and how everyone gets the merged work. Different files make merging easier; run the app after combining changes.

Submission checklist

  • Core interaction and 1–2 stretch goals
  • Initial class diagram or UML draft
  • Team ownership and next-task table
  • GitHub repo URL
  • Evidence that the starter app runs
  • Each teammate’s merged PR URL, labeled with their name

Use the team submission process already used in the course. One member should submit the work, and the team should confirm the correct names are visible.
