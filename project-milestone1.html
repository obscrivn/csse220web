Use a local folder outside OneDrive and other cloud-sync folders. Create a CSSE220 folder directly in your user/home folder. Desktop and Documents may be synced automatically; check the full path. See the guide for Windows and macOS examples.

Follow the numbered GitHub setup guide in order. Stop at each checkpoint before continuing. Do not create separate repositories for each teammate.

What is required now vs. later

Milestone 1 focus

  • Choose a user and a small meaningful interaction.
  • Draft the main classes, data, and responsibilities.
  • Get the JavaFX starter running in a shared team repo.
  • Practice a safe branch → review → merge workflow.
  • Submit a clear design summary and team plan.

Later project work

  • More game/app features
  • Polished UI or animations
  • Multiple screens or levels
  • Testing, debugging, and final showcase

Milestone steps

  1. Step 1: Define the user. State who the app is for, what problem it solves, and the first 30 seconds of the experience. Ask: What does the user do first? What should the app show immediately?
  2. Step 2: UML draft. Sketch the main classes, fields, methods, and relationships. Write a short explanation for why the design makes sense.
  3. Step 3: Starter and Git setup. One setup lead downloads and runs the starter, initializes and publishes the team repository, and invites teammates. Other teammates accept, clone, open, and run that repository.
  4. Step 4: Branch workflow. Each person should create a feature branch, make a small independent change, commit, push, open a PR, review, merge, and sync main.

This milestone is about building an initial product direction and a working team process. You are not expected to finish a polished game yet.

Follow the numbered GitHub setup guide.

GitHub Desktop branch workflow

Follow the guide in order: the setup lead downloads → runs → initializes → publishes → invites. Teammates accept → clone → open → run. Everyone then creates a branch from updated main, edits a different file, commits, pushes, and opens a pull request.

Open the step-by-step GitHub Desktop guide. It includes separate setup paths, branch switching, file ownership examples, review and sequential merges, and pulling the combined result.

For the first exercise, create separate files such as docs/idea.md, docs/design.md, and docs/team-plan.md. These are not included in the starter. Do not all edit StarterApp.java. Each student should show their own commit and merged PR; different files reduce conflicts but the combined app must still be checked.

Submission checklist

  • Core interaction and 1–2 stretch goals
  • Initial class diagram or UML draft
  • Team ownership and next-task table
  • GitHub repo URL
  • Evidence that the starter app runs
  • Each teammate’s merged PR URL, labeled with their name

Use the team submission process already used in the course. One member should submit the work, and the team should confirm the correct names are visible.
