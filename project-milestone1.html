What is required now vs. later

Milestone 1 focus

  • Choose a user and a small meaningful interaction.
  • Draft the main classes, data, and responsibilities.
  • Get the JavaFX starter running in a shared team repo.
  • Practice a safe branch → review → merge workflow.
  • Submit a clear design summary and team plan.

Later project work

  • More game/app features
  • Polished UI or animations
  • Multiple screens or levels
  • Testing, debugging, and final showcase

Milestone steps

  1. Step 1: Define the user. State who the app is for, what problem it solves, and the first 30 seconds of the experience. Ask: What does the user do first? What should the app show immediately?
  2. Step 2: UML draft. Sketch the main classes, fields, methods, and relationships. Write a short explanation for why the design makes sense.
  3. Step 3: Starter and Git setup. Clone or create the shared repo, import the starter, and verify the app launches.
  4. Step 4: Branch workflow. Each person should create a feature branch, make a small independent change, commit, push, open a PR, review, merge, and sync main.

This milestone is about building an initial product direction and a working team process. You are not expected to finish a polished game yet.

GitHub Desktop branch workflow

  1. Accept the team repository invitation or confirm the repo exists.
  2. Clone the shared repository.
  3. Open it in your IDE and make sure the main branch is current.
  4. Create a named feature branch such as ui-start-screen or uml-notes.
  5. Make a small independent edit.
  6. Review the changed files.
  7. Commit locally.
  8. Publish or push the branch.
  9. Create a pull request on GitHub.
  10. Have a teammate review it.
  11. Merge the PR and then sync main locally.

Important: commit saves your work locally, while push sends it to the remote repository. A pull request is not the same as a pull command. Use main as the shared baseline, not as the place for ad hoc direct edits.

Instructor GitHub demo guide

During class, the instructor can demonstrate the flow in a few minutes:

  1. Create a throwaway demo repo from the starter.
  2. Invite a second account or teammate as a collaborator.
  3. Clone the project and open it in the IDE.
  4. Create a feature branch.
  5. Change a small file such as a note or label.
  6. Commit, push, and open a pull request.
  7. Review the change on GitHub.
  8. Merge the branch and pull the updated main branch.

Keep the demonstration small and focused so students see the exact workflow without relying on a perfect project implementation.

AI Team Coach

Your team may use AI as a tutor, but the idea and design should come from your own discussion. Use AI to ask clarifying questions, explain a class relationship, or help debug a small Java issue. Do not let AI write the plan for you.

  • Ask AI to explain one class relationship at a time.
  • Require the AI to justify suggestions.
  • Explain the result back to the team before implementing it.
  • Keep an AI usage log if your instructor requires one.
