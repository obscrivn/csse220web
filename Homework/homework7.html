LinkedList coding review

Use this review to get started if we did not reach the coding examples in class. The examples use the supplied ListNode and SinglyLinkedList classes.

1. Create and connect nodes

A node stores an Integer element and a ListNode next reference. The reference tells us which node comes next. A null next reference marks the end.

ListNode first = new ListNode(10);
ListNode second = new ListNode(20);
first.next = second;

new ListNode(10) creates a node containing 10 with next == null. Assigning first.next = second connects the two nodes. It does not copy the second node.

first → [10 | next] → [20 | null]
                      ↑
                    second

The two-argument constructor can connect a new node to an existing chain:

ListNode start = new ListNode(5, first);
// start → [5] → [10] → [20] → null

Here first still refers to the node containing 10. Creating start does not automatically change another reference. These local variables illustrate nodes; inside your list class, this.first and this.last record the list's endpoints.

2. Traverse with a while loop

Start a temporary reference at the first node. Process its value, then follow next. Stop when the reference becomes null.

ListNode current = start;
while (current != null) {
    System.out.println(current.element);
    current = current.next;
}

For the chain above, this prints 5, 10, and 20 on separate lines. The assignment moves current; it does not move nodes or change their links. Keep the starting reference so the list remains accessible.

Predict and explain

What happens if the chain is empty? What happens if you omit current = current.next? Why would while (current.next != null) miss the final value?

Check your reasoning

An empty chain starts with current null, so the body runs zero times. Without the update, a nonempty chain repeats the same node forever. Checking current.next stops before processing the last node and dereferences null on an empty chain.

3. Use the list's methods

These examples show the expected behavior after you implement the relevant TODOs. They are calls to your custom list, not java.util.LinkedList. You can try them in a separate scratch main method or your own test.

SinglyLinkedList numbers = new SinglyLinkedList();
numbers.add(10);
numbers.add(30);
numbers.insertAtIndex(1, 20);      // [10, 20, 30]
System.out.println(numbers.size());        // 3
System.out.println(numbers.contains(20));  // true
System.out.println(numbers.indexOf(30));   // 2
Integer previous = numbers.set(1, 25);     // returns 20; [10, 25, 30]
boolean removed = numbers.remove(10);      // returns true; [25, 30]

Indices start at zero. Inserting makes room for a new element; setting replaces an existing element. Removing uses a value, not an index.

SinglyLinkedList repeated = new SinglyLinkedList();
repeated.add(8);
repeated.add(8);
repeated.add(3);
repeated.remove(8);              // [8, 3]; removes the first 8 only
int position = repeated.indexOf(8);  // 0
boolean found = repeated.remove(99); // false; list stays [8, 3]

Bracketed comments show element order. The supplied toString() also displays first and last values for a nonempty list.

4. Plan one operation at a time

Start with add, then size. Before changing links, draw an empty list, a single-node list, and a longer list. Identify which references must change and which must stay the same. Implement one TODO, run its tests, then compare the result with your drawing.

When searching, compare Integer values with equals, such as current.element.equals(target) for the non-null inputs in this homework. Using == compares object identities and can appear to work for some small Integers while failing for other equal values.

The seven operations

  • add(Integer element): append the element.
  • size(): return the number of nodes.
  • insertAtIndex(int index, Integer element): insert at index 0 through size inclusive. Insertion at size appends; invalid indices throw IndexOutOfBoundsException.
  • contains(Integer element): return whether an equal Integer value is present.
  • remove(Integer element): remove the first matching value and return true; return false if absent.
  • indexOf(Integer element): return the first matching index, or -1 if absent.
  • set(int index, Integer element): replace at index 0 through size minus one and return the old value. Invalid indices throw IndexOutOfBoundsException.

Compare Integer values rather than object identities. Invalid-index operations leave the list unchanged. Graded inputs use non-null Integers; null handling is not an additional requirement.

[2, 6] → insertAtIndex(1, 7) → [2, 7, 6]
[2, 7, 6] → set(1, 9) returns 7 → [2, 9, 6]
[2, 9, 6] → remove(2) returns true → [9, 6]

Keep the representation consistent

Use the supplied nodes. Keep package declarations, public signatures, node classes, and supplied methods unchanged. An empty list has both first and last null; a single-node list has both references pointing to the same node. The final node's next reference is null.

Predict before testing
