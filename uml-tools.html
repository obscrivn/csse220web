UML Tools & Instructions

PlantUML turns text into diagrams. A .puml file is editable diagram source, not Java code or an image. In CSSE220, class diagrams help us make data, behavior, and relationships visible so we can reason about a design.

Install · Generate from Java · Create and preview · Add arrows · Troubleshooting

Two plugins, two jobs

PlantUML Parser: generator

Inspects existing Java files and writes PlantUML source. Use it after coding to see the structure you implemented.

PlantUML Parser on Marketplace

PlantUML4Idea: renderer

Supports editing and rendering PlantUML inside IntelliJ. Use it with generated source or a diagram you write before coding.

PlantUML4Idea on Marketplace

Code → UML: Java classes → PlantUML Parser → .puml source → PlantUML4Idea → rendered diagram.

Design → UML: Understand the scenario → model classes, data, behavior, and relationships → write .puml → preview → critique → implement.

Generating UML does not evaluate your object-oriented design. It describes the code that exists. Use the CSSE220 design principles and ordered checkdown: functionality, structure around the data, responsibility, dependencies, and duplication.

1. Install both IntelliJ plugins

  1. Open your Java project in IntelliJ IDEA.
  2. Open File → Settings on Windows/Linux, or IntelliJ IDEA → Settings on macOS (called Preferences in older versions).
  3. Select Plugins → Marketplace. Search for PlantUML4Idea and click Install on the plugin linked above.
  4. Search for PlantUML Parser and install that separate plugin too.
  5. Apply the changes. Restart IntelliJ if prompted, then check Plugins → Installed to confirm both are enabled.

Checkpoint: Follow the small manual example below to verify rendering before generating a larger diagram. If Marketplace reports incompatibility, bring your IntelliJ version and the plugin error to your instructor.

2. Generate UML from existing Java

  1. Save your Java changes. In IntelliJ's Project pane, expand src (or src/main/java for Maven projects).
  2. Right-click the package folder containing your assignment's Java classes, such as lab or exam. For a single class, right-click its .java file. Avoid selecting the whole project if you only need one package.
  3. Select PlantUML Parser from this Project-pane context menu.
  4. In ParserConfig, enter an output filename such as final-design.puml. Check the complete output path displayed in the dialog so you know where it will be saved.
  5. Review field and method visibility options. Include the private fields needed to show stored data, and follow the assignment's requirements for methods and constructors.
  6. Click generate. The plugin writes the source and opens it in the editor. If needed, find the output path in the Project pane and double-click the file.
  7. View it using PlantUML4Idea as described below. Compare class names, fields, and relationships with your Java code; add missing relationship arrows only when the code supports them.

Checkpoint: Can you point to a Java field or declaration that explains each relationship? A generated diagram is a snapshot. Generate again after changing Java.

3. Create, edit, and preview a .puml file

  1. In the Project pane, right-click a project folder and choose New → File. Name it practice.puml. This also works when a plugin-specific file template is unavailable.
  2. Paste the example below. Keep @startuml and @enduml; they mark the diagram's boundaries.
  3. Save the file and keep it open. PlantUML4Idea supplies a diagram preview. If hidden, look under View → Tool Windows → PlantUML.
  4. Change the field name or add a method, save, and check the preview. Editing this file changes the diagram, not your Java classes.
  5. If the assignment requests an image, use the preview's export/save control, select PNG, and open the saved image to check readability. Submit the format requested by the assignment; a .puml source file is different from a PNG/JPG.
@startuml
class Player {
  - name : String
  - score : int
  + addPoints(points : int) : void
  + getScore() : int
}
@enduml

- means private; + means public. Fields store data; methods describe behavior. This example is diagram practice, not an assignment solution.

4. Add relationships the generator missed

Keep the course UML cheatsheet (PDF) nearby. A field listed in a class box may still need an arrow to show the relationship clearly. Check the Java first; the generator cannot infer every intended constraint.

  1. Find the field or declaration that establishes the relationship.
  2. Add a relationship line before @enduml, using the exact class names or aliases already declared in the file. Generated names may include the package, such as lab.Player.
  3. Save and inspect the arrow direction and multiplicity. Avoid adding a second arrow if the relationship is already present.
@startuml
class Player {
  - items : ArrayList<Item>
}
class Item {
  - name : String
}
Player --> "0..*" Item : items
@enduml

If a player stores a list of items that may be empty, this association shows that a player can reference zero or more items. It does not assert that items cannot be shared between players. During practice, showing both the field and the arrow helps connect Java to UML; they represent the same relationship, not two collections.

Other relationship lines, when supported by the code
Java evidencePlantUML lineMeaning
Player stores one Inventory referencePlayer --> "1" Inventory : inventoryUse 1 only if the reference is required and non-null; use 0..1 if optional.
Player extends GameObjectPlayer --|> GameObjectInheritance; hollow triangle points to the superclass.
Player implements HealablePlayer ..|> HealableInterface implementation; dashed line points to the interface.
A method temporarily uses an Item without storing itPlayer ..> Item : usesDependency, rather than a stored association.

Declare the endpoint classes/interfaces if not already present. Do not turn every field into an arrow: score : int is an attribute. Do not choose composition just because one class stores another; composition makes a stronger ownership/lifetime claim.

Test your thinking: If items becomes one optional Item reference, what multiplicity would you show, and what code would justify it?

Troubleshooting

PlantUML Parser option is missing
Right-click a Java file or package folder in the Project pane, rather than inside the editor or the rendered image. Check that Parser is installed and enabled; restart if requested.
Preview is missing
Open a .puml file with a complete @startuml/@enduml block. Check PlantUML4Idea is enabled and open its PlantUML tool window. Try the small Player example to distinguish a setup problem from a source error.
.puml opens as plain text
The source is text, but a preview should be available. Confirm the filename ends in .puml, not .puml.txt, and check PlantUML4Idea. If you previously associated .puml with Text, inspect Settings → Editor → File Types and remove that conflicting pattern before reopening.
Preview shows a syntax or Graphviz error
Fix the reported source line first. If it explicitly reports missing Graphviz/dot, use the renderer's linked documentation for your operating system, then restart IntelliJ. Do not reinstall Parser to fix a rendering dependency.
Diagram does not reflect recent Java changes
Save Java, run Parser again, and open the new output file. Preview refresh renders the current .puml; it does not re-inspect Java. Keep a copy of manual arrow edits before regenerating and recheck them against the new code.
Too many classes appear
Generate from the assignment package or selected Java files instead of the project root. Check that test and unrelated packages are outside your selection.
Installation requests a restart
Save your work, restart IntelliJ, and verify both plugins under Installed before trying again.
